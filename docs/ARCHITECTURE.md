# 当前架构与运行链路

更新于 2026-11-14。古代世界六条 IF 均采用人工事件组；边境、逐鹿共用事件协议 2、运行版本 22，见[边境作者表](FRONTIER_BRANCH_PILOT.md)和[事件协议](EVENT_FLOW_IMPLEMENTATION.md)。其他古代路线保持版本 20，其他世界保持版本 18。两条样本旧局只读、不迁移；执行能力按协议选择，不按 IF ID 或军职选择。

## 职责与唯一来源

| 层 | 来源 | 职责 |
| --- | --- | --- |
| 世界设定 | `data/worlds/`、`data/narratives/*.story.json` | 共同世界、力量目录、属性与生存规则 |
| 局部世界知识 | `data/narratives/world-cards/` | 制度、地域、组织与行动知识；适用规则原文按引用选入本幕 |
| IF | `data/narratives/story-packs/` | 家庭入口、三幕方向、准入与实际收束标准、结局边界 |
| 人工事件组 | `data/narratives/event-flows/` | 已配置路线的完整节点、三档行动、确定成败对应结果和预设资产 |
| 本幕主持资料 | `actRuntime.outline` | 本局选定的局势、行动方、空间、压力、利益及规则；本幕内固定 |
| 实际历史 | 已提交正文、玩家选择与结果 | 已发生内容；摘要只替换准确覆盖的对话来源 |
| 展示资产 | 连续性维护结果与回合快照 | 前端角色卡，不反向成为正文任务或世界卡事实 |

模型判断语义，代码处理身份、引用、数值、年龄、掷点、库存、保存及重试。节点结果不等于整幕收束；展示同步成功不决定已经发生的故事是否成立。

## 边镇事件组完整链路

### 开局与幕初

1. 开局快照所选 IF 和事件骨架。身世请求接收人设、天赋、共同设定及家庭入口，生成出生正文与预设身份名称，没有独立身世摘要。
2. 出生正文成功提交后，唯一异步入口组织第一幕。后续幕在前幕实际收束、新幕建立后启动。
3. 幕初只组织 `situation / actors / locations / pressures / stakes` 并绑定角色名称，不选择事件组。协议 2 的首组来自素材 `actEntries`，后续来自已提交结果的接续范围；单候选直接承接，多候选才由幕内规划选择。
4. `objective` 原样取 IF，`closureMeaning` 来自 IF 的 `payoffMeaning`。制度规则通过 `worldRuleRefs` 选择实际已供应原文，存入 `worldRules`。
5. 待卡期间最多两次成功提交的过渡生活；就绪后按既有准入进入准备或剧情，不补满缓冲。缓冲用尽则等待，不继续增加年龄。

幕卡是开幕局势。后来的任职、失败、伤亡及移动以实际历史为准，不重写幕卡，也不将历史里出现过的动作升级成新的手续要求。出生输入的完整溯源见[本批记录](PERIOD_MEMORY_AND_EVENT_ROUTING.md)。

### 准备与组内执行

- 每幕关键属性分别达标后，准入持久化；属性下降不撤销。
- 配置了 `entryRequirements` 的事件组可在组前补强。普通生活按实际正文结算成长；流派与不足属性分别承担行动方式与准备依据。
- 当前组未完成时沿本组下一节点执行，不抽新组。正文只接收当前节点，不接收未选成败分支作为事实。
- 用户认可第二幕 `border-campaign` 试点后，边镇线 13 组、41 单元均采用 `routing=planned`。规划在完整单元提交后只返回下一单元 ID；军议使用 `settlement` 的明确规则，由正文提交适用规则 ID 并落实处置，引擎只校验及提交对应结果。显式出口结束组，存活决战结果接军议与战后生活；战死直接观察结局。旧顺序组快照保持原执行方式，见[试点](FRONTIER_CAMPAIGN_PILOT.md)与[推广](FRONTIER_EVENT_ROLLOUT.md)。
- 普通节点落实给定经历；抉择节点停在玩家作答前。节点指定核查属性与难度，沿用现有概率公式与单次持久化掷点。
- 结果正文取得已选行动和确定成败，结束本次事件。玩法道具按对应结果增减；展示维护无权改变库存。

### 时间与可恢复提交

边镇事件单元可配置 `lifeBefore`，引擎按本局种子一次选择并保存生活间隔。未满时使用普通年份入口，按实际提交年龄消耗；组前准备同时计入，重试不消耗。生活不完成目标单元，不读取其预写结果或选项。无配置的连续行动直接承接，见[普通生活链路](ORDINARY_LIFE_INTERVALS.md)。

`sceneClock.mode` 只表示下一段采用的方式。剧情正文与独立结果必须提交 `nextClock: hold | advance`；引擎在下一段生成前确定年龄。

`hold` 允许本岁内继续经历，并不限于下一分钟；换组和换幕不强制跨年。抉择背景、选择、结果和求生属于同一事件年龄。失败请求不提交新的时间；已保存结果的重试不重写正文或重新掷点。

正文、确定性结算及待收尾来源先保存。后续通过 `pendingActFinalization` 恢复原事件收尾，不先生成一段新故事。玩法库存按来源只应用一次；待选和求生未处理完，不换幕或进入结局。

### 收束与接组分别执行

完整组结束后：

1. `observe_act_closure` 读取完整主持资料、IF 标准及实际历史；不读下一组候选。
2. 返回 `ongoing` 时调用独立 `plan_next_event_flow`，读取当前年龄与属性、上一组结果、实际历史和本幕合法候选，只选择下一组。
3. 返回 `act_closed` 时记录本幕结果并建立下一幕；返回 `run_ended` 时保存结局依据与等级，以及适用的生死和死因，进入现有结局表达。
4. 观察与接组结果分别暂存。规划失败只重试规划，不重观察、重结算或重掷点。候选为空保留待处理来源并报告接组缺口，不要求观察器改判结束。
5. 最后一幕不能仅提交换幕；纠正请求同时允许 `ongoing / run_ended`，不预设必须马上结局。

未配置人工事件组的路线，正文自由主持整幕发展，保留其完整事件提交与收束观察入口。

## 连续性展示维护

普通完整经历三次、完整抉择结果、幕末与终局提供维护机会，重合只处理一次。保持前台等待，失败保留批次，在之后正常机会合并重试，不要求重写已保存故事。

配置事件组的路线只整理本批事件组预设身份及身世身份。人物记录伤亡与关系，地点记录可用／控制状态，本领记录掌握程度，道具记录持有／损坏状态。性质和方法取人工素材，不由维护追加经历或 `usage`。当前所在地保留最简身份。

连续性不进入正文、幕初规划或结局材料。未配置事件组的路线保留各自维护协议，不把预设枚举误说成已推广所有路线。

## 分时段历史

1. 沿用十年、幕末与终局机会，选择尚未覆盖的完整实际对话。
2. 模型只收到本时段范围与正文，返回大事概要；不再收到旧摘要重写完整人生。
3. 引擎追加本时段摘要，以精确来源集合覆盖本批原文。年龄用于时段展示，不替代来源 ID；同年新段不被误覆盖。
4. 后续请求只从 `story-history.ts` 取得各时段概要与未覆盖原文。选择背景、实际选择和结果完整衔接，未选分支不作为历史。
5. 后台结果校验读取版本与来源；失败继续供应原文，期间新增故事留待后批。归并和恢复保留独立时段摘要，不按共同 `scope` 折叠。

压缩仍有时保留训练和战术细节；按时段替换正确与摘要筛选质量分别验收。没有字数合格线、截断或二次整理请求。

## 提示词与缓存边界

供应顺序为：**固定职责与工具 → 本幕稳定资料与稳定人设 → 故事历史 → 当前状态与本轮任务**。

- system 职责集中在 `narrative/task-contracts.ts`，固定工具解释字段与提交方式。
- 观察器取得收束含义，正文取得主持资料和本幕方向；同一材料不经不同栏目重复注入。
- 结局取得稳定人设、同一份实际历史和已确认结果；不接收面向下一段行动的能力／学习方式、重复最终数值及最新处境续写标记。数值展示与结局等级裁定保留各自入口。
- 年龄、属性、候选 ID、检定与查询结果不进入 system 或动态 schema 枚举。
- 世界文体、文风、表达样例和旧收益指导已经退出当前供应。
- 会话恢复重建当前 system，保留已提交实际历史；不把旧会话摘要再供应一遍。
