# 项目架构（v1.0.1）

## 增量对齐：2026-09-21 +08:00 — 三世界 IF 横向扩展与场景协议

- 古代权谋、现代都市、奇幻世界均已迁移为 v10 基础世界，并各自提供六条独立 IF 子世界包；三个基础世界都不再内置 `storyPatterns / mainlineSkeleton / mainlineActs`。
- 动态场景最多同步六名需要身份、关系或后续连续性的具名参与者。人物召回、场景焦点和全局人物档案仍保持各自边界；无名人群只存在于正文。
- 结构化场景结算先校验人物、属性和幕交接，再请求玩家正文，避免无效结算继续消耗渲染请求。
- 本领继续使用稳定 `name` 作为档案标题；`mastery` 是简短掌握状态，完整用途、局限和来历在展开内容中展示。

## 增量对齐：2026-09-21 +08:00 — v10 基础世界与 IF 子世界包

- 当前生产入口将世界内容拆为基础世界与可独立发现的 IF 子世界包。基础世界只持有共同世界观、社会力量、叙事调色板、世界卡、成长、生存和世界级结局；子世界包以自身 `worldId` 归属世界并持有路线承诺、入口视角、三幕目标和路线结局方向。
- `story-packs.ts` 递归扫描 `data/narratives/story-packs/**/*.json` 并校验 ID、世界归属、三幕、社会力量引用和路线卡作用域。基础世界不保存子包清单，前端也不维护路线枚举。
- 新局入口先校验玩家选择的 `storyPackId`，再由 `narrative-experience.ts` 把基础世界与子包组合为现有运行时所需的 `mainlineActs / mainlineSkeleton / endingBlueprints`。Agent、五拍、属性、死亡、事实、人物、地点、本领与结局状态机继续使用同一链路。
- 所选子世界包写入 `InternalRunState.storyPackSnapshot`。步进与恢复只读取该快照，因此内容作者调整磁盘 JSON 不会改写进行中的人生。
- 三个内置世界均已迁移到 v10 并提供六条可选 IF 路线；不存在旧自由模式回退。
- 下方 v9 及更早章节保留为架构演进记录；当前生产入口以本节为准。

## 增量对齐：2026-09-20 03:44 +08:00 — v9 本局故事前提与语义节拍观察

- 当前三个内置世界包使用 v9 结构。`worldCore` 只声明世界身份、稳定规律与可能性；`socialForces` 声明会行动的社会力量；`narrativePalette` 提供生活、冲突、行动与反思的题材词汇；`storyPatterns` 是 Planner 可选 0—2 项的故事形态素材。它们都不是必须走完的路线，也不承担节拍准入。
- `mainlineActs` 只保留三个长期结构槽。身世成功后，独立的 `establish_session_premise` 请求依据玩家人设、最终天赋、身世和世界核心生成本局人物锚点、核心张力、故事承诺与三个结构段的问题。具体案件、职业、敌人、组织和人生目标由本局前提与已发生事实形成，不再由世界包预写。
- 当前动态链路为 `Session Premise → Horizon（按需）→ Turn Planner → 精确召回 → Renderer → Prose Review → Beat Observer → Engine Settlement → Commit → Curator`。Planner 可不选故事形态和社会力量；Renderer 只消费选中的素材及本局状态，不接收固定路线目录。
- `observe_story_beat` 是独立语义观察请求，只能返回 `hold / advance`、正文证据和少量关键词。它不生成正文、不写事实、不选择结局；规则引擎结合当前拍点执行真正的状态迁移。抉择场景先保持当前拍，玩家后果渲染完成后再观察。
- 三段人生结构均沿用 `setup → escalation → pressure → climax → payoff`。属性门槛仍控制人物是否具备进入相关阶段的能力，普通年份仍承担年龄与成长缓冲；没有恢复年龄上限或固定剧情候选池。
- 非死亡结局在三个结构段完成、事实与抉择要求满足后开放申请。v9 只要求世界级 `good / normal / bad` 三张结局蓝图；属性、名望、天赋与代价决定结局品质，不再寻找最终路线对应蓝图。
- 下方 v8 及更早的路线、阵营与静态事件记录保留为演进历史；它们不代表 v9 内置世界的当前动态入口。

## 增量对齐：2026-09-16 19:05 +08:00 — 世界卡生命周期与上下文契约收口

- 世界卡激活明确区分 `direct / related / sticky`。只有直接命中和首次关联命中会写入激活状态；Sticky 消费既有期限，不续期、不重复扩散，结束后按提交 Episode 序号进入 Cooldown。
- Sticky 只绕过正文关键词，不能越过任务、世界幕、拍点、路线、阵营、事实与局内对象作用域。关联卡同样经过作用域、冷却、互斥组和预算检查；未进入最终上下文的卡不会持久化。
- 世界卡任务协议收口为 background、planning、horizon、rendering、dynamic、decision。Horizon 请求前单独构建 horizon Prompt Plan，结束后恢复单回合 planning 计划，不新增模型请求。
- v8 世界包只读取非空 `worldCards`；v1—v7 才读取旧 `lore`。三个内置世界和社区模板的重复 lore 已清空，风格卡改为真实短叙事示例。
- 场景提交地点／本领后，引擎把稳定 ID 写入待决场景；抉择请求精确召回该场景资产。动态导演签名不再携带未消费的旧事件、道具和路线表参数。
- 内部 Context trace 增加激活种类、最近激活序号、剩余 Sticky/Cooldown 和排除原因；前端协议、年龄、属性、生存、结局与存档规则不变。

## 增量对齐：2026-09-16 11:48 +08:00 — 情景世界卡与按需召回

- 世界包版本升级至 v8。世界卡不再只是按世界幕、拍点和路线匹配的规则片段，还可声明关键词、辅助关键词逻辑、扫描深度、注入位置、关联卡、粘滞与冷却；匹配对象是当前任务、近期真实叙事和本轮明确关注的事实／人物／地点／本领。
- Context Provider 将卡片分别投影到世界常量、场景资料、表达样例和当前场景关注层。完整路线目录仍只在 Planner 中开放；Renderer 只获得计划选中的路线、阵营和情景材料，世界卡不拥有状态机裁决权。
- 人物、事实、地点和本领继续使用既有局内状态与稳定 ID，但工具引用合同收窄到本轮召回对象，避免存档越长，Prompt 和工具枚举越大。已解决事实保留在历史摘要或明确召回中，不重新成为待解决问题。
- 当前三个内置世界包改用统一 v8 结构。古代包停止在运行时合并旧 `components.json` 硬事件目录；现代与奇幻补充了生活制度、空间、组织、能力、冲突土壤和分任务表达样例。五拍、年龄、属性、生存、结局与匿名存档链路不变。
- 设计基线见 `docs/NARRATIVE_WORLD_CARD_DESIGN.md`；社区世界包示例和说明同步覆盖 v8 字段。

## 增量对齐：2026-09-15 13:21 +08:00 — 叙事 Agent 阶段 6—8

- `NarrativeRunState.version=9` 新增分作用域 Memory Digest、幕间 Horizon Plan 和不含正文／提示词的 Agent Attempt 引用记录。Curator 只整理已经原子提交的 Episode，不创造事实；以 `memoryRevision` 和 Episode 覆盖范围进行异步 CAS 提交，失败不阻塞游戏。
- 长期召回改为“相关 Digest + 尚未覆盖的 Episode + 本轮明确关注的原始 Episode + Act Canon”。Digest 成功后同步投影为 conversation `headMemory`，旧 archive 摘要不再作为并行写入任务，避免两个摘要系统竞争。
- 非纯背景回合在每幕建立建议性的 Horizon：描述当前幕值得发展的张力、近期意图和可能的阶段结果。它不包含候选路线白名单，不创建事件、人物或结局；单回合 Planner 仍从世界包完整路线／阵营目录自由选择。重大抉择与 payoff 只将 Horizon 标记为待更新。
- `narrative/runtime.ts` 统一编排准备、Horizon、单回合计划、精确召回、渲染、正文整理和提交追踪。普通背景保持一次请求；主线场景、抉择结果与结局增加正文整理请求，整理器只能修改玩家文本，不能改变属性、事实、人物更新、选项或状态机结果。
- Context Collector 拆为显式有序 Provider：人物稳定层、世界幕、Lore、人物、事实、资产、长期记忆、结局和当前任务。世界包仍是数据配置，不获得可执行插件权限；未引入 RAG、外部工具或新的前端协议。

## 增量对齐：2026-09-15 12:32 +08:00 — 叙事 Agent 规划、原子提交与阶段记忆

- 动态导演改为 `NarrativeTurnEnvelope → plan_narrative_turn → 精确二次召回 → 单一渲染工具`。Envelope 只投影引擎拥有的年龄、世界幕、五拍节奏、允许回合类型、世界包路线／阵营目录、属性档位、成长侧重和场景时钟；模型计划只选择背景或场景、路线、阵营、关注引用、场景目标、呈现类型与时间请求。
- 纯背景回合仍保持一次模型调用；只有场景与背景均可用、或需要场景规划时才增加规划调用。规划结果不写入 conversation，不修改年龄、节拍、属性、事实、人物、资产或结局状态。渲染前按已选路线、阵营和引用重新构建上下文，并把工具 schema 收窄到唯一呈现方式。
- `runStepFlowUnlocked` 原有“读取存档后先克隆、成功后统一保存”的事务边界继续负责整个 step；身世生成也改为先在副本完成再发布。模型、解析或引擎校验失败时不产生部分事实、资产、记忆、时间线或存档提交，也不切换成普通背景或本地模板。
- `NarrativeRunState.version=8` 新增只保存引用的 `episodes[]` 与由 payoff `actHandoff` 派生的 `actCanon[]`。正文仍只存在于既有 memory/TurnRecord；Episode 关联 call、来源事件、幕／拍、路线／阵营及事实、人物、地点、本领引用，Act Canon 保存已完成世界幕的矛盾结果、持续代价与后续处境。
- 召回顺序为活动场景、规划显式关注对象、当前幕近期 Episode、前幕 Act Canon、相关旧 Episode。已被 Act Canon 表达的 payoff Episode 不重复注入全文；本阶段仍是确定性本地索引，不引入 RAG 或异步 curator。

## 1. 架构目标
- 玩法计算与 AI 文本生成解耦

## 2. 分层设计

### 2.1 前端层（`apps/frontend`）

## 3. 核心时序（流式）

### 3.1 开局
1. `POST /api/game/start/stream`
2. 后端创建 run，先推进 raw chunk
3. `started` 事件先下发（无 milestone）
4. 年份叙事 AI 完成后逐条 `timeline`
5. milestone 文案 AI 就绪后再发 `milestone`
6. 最后 `done`

### 3.2 推进
1. `POST /api/game/step/stream`
2. 无抉择则自动推进；有抉择则先结算抉择再推进
3. 逐条 `timeline`
4. 有新抉择再发 `milestone`
5. `done`

## 4. 抉择链路要点
- 触发：阶段概率、保底年数与世界观 `milestoneAges`
- 最低触发年龄：`minEligibleAge`
- 背景种子：`data/events/faction-events.json` 会兼容归一为带 ID、冷却和阵营标签的事件卡
- 事件元数据：`data/events/event-metadata.json` 逐条补充年龄窗、叙事位置、方向标签、主次属性、权重与冷却；加载时与原始事件文本合并
- 天赋和命运道具会影响候选权重、负面变化与死亡风险
- 文案：AI 先在工具调用中选择事件方向；引擎确定具体事件后，AI 再根据工具回执渲染叙事与抉择文案
- 数值：引擎按事件专属后果计算，模型不能修改属性、掉落或结局
- 幼年阶段仍受 `deltaCapByStage.child` 限制

阶段 2：导演运行态复用既有 `StoryDirectorState`，在事件结算后记录方向标签、语义 flags、阻断 flags 与结构完整性缓冲。缓冲以起点、积累、压力、转向、结果五类事件计数，并仅标记是否具备未来“请求结局引导”的最低结构条件。

兼容边界：旧随机推进不读取也不写入该状态；其候选筛选、数值结算、死亡/飞升阈值与前端展示均保持原样。工具模式则按阶段 4/5 的主线与收束规则运行，内部状态始终不会暴露给前端。

阶段 3：`aiConversation.year` 的既有压缩会话现可保存文本消息、模型工具调用和引擎结算回执。导演工具成功后，只有事件被引擎结算才写入该完整回合；近期三轮保留完整工具记录，归档摘要仍只压缩用户输入与最终叙事。为兼容本地 OpenAI 接口，历史工具记录在下一次请求时投影为普通的用户/助手成对消息，不直接发送历史 `tool` role。

阶段 4：`tool-fast` 使用两段式导演。引擎先按年龄、冷却、主线位置、前置 flags 和阻断 flags 筛出合法事件，并合并为最多六个方向标签；模型只能工具调用 `select_event_focus` 选择方向。引擎随后按候选权重和本局种子确定具体事件，将该事件素材作为 `tool` 回执交给第二次模型调用渲染。工具不支持或第一段调用失败时，仍由引擎选取方向池首项并使用本地叙事回退。

阶段 5：工具模式的结构完整性达到最低条件后，模型可调用 `request_story_closure` 申请 `guide` 或 `finish`。引擎只会在至少出现一个结果事件、且没有待选抉择时批准结束；未达到该门槛的申请会转为引导期，并优先投放结果类事件。飞升仅作为可供结局消费的成果，寿命上限只提供收束节奏，不再直接终止工具模式；死亡仍立即结束。获批后使用既有结局文案生成完成最终结算。

阶段 6：古代世界的原始事件、事件元数据和叙事绑定均以同一事件 ID 对齐。每条事件同时具有可用年龄、冷却、权重、主副属性、后果画像、状态旗标与叙事节拍；前端以阅读器布局展示既有流式时间线、抉择、天赋、道具与结算，不参与状态判定。

## 9. 运行时对齐记录（2026-08-15 01:22 +08:00，增量）

> 本节只追加当前实现，不改写上方历史阶段记录。若与第 2.4、4 节中关于 `select_event_focus`、年龄收束或工具回退的旧描述冲突，以本节为准。

### 9.1 已启用的叙事边界
- 叙事世界包由 `data/narratives/<worldId>.story.json` 提供；当前完整落地的是 `ancient`，其他世界不会因该运行时被强行套入古代主线。
- 世界包提供主线骨架、路线属性门槛、背景段落节拍、组件/人物/Lore、事实绑定与双向结局蓝图。引擎只将当前阶段所需的紧凑投影送入模型。
- `StoryDirectorState` 保存路线承诺、事件 flags、事实账本、`mainlineCompleted` 与结局状态；`NarrativeRunState` 保存活跃场景、线索组件、高潮/回收计数及已锁定的结局蓝图。
- `TurnRecord` 是前端可见的原子回合投影。路线、标签、账本、工具记录和候选池属于服务端内部状态，不作为玩家界面内容。

### 9.2 当前叙事与工具链
1. 无活跃场景时，引擎按世界包的背景节拍生成可变年龄跨度的成长段；普通段承接既有事实和人物余波，不展示内部路线或阶段标签。
2. 达到路线属性门槛并满足前置事实后，引擎开放 `setup`、`pressure`、`climax`、`payoff` 等合法候选。抉择结果写入事实账本，后续事件只能修改或回收已真实建立的事实。
3. 模型不选择具体事件、数值、掉落或结局。常规导演回合只能调用 `propose_story_intent` 提出延续、加压或回收意图；`tool-gateway.ts` 再从引擎候选中批准唯一事件，第二次模型调用只渲染该事件文本。
4. 压缩会话保留近期已结算的叙事与工具回执，叙事计划按需投影世界事实、关键事实、活跃线索、人物与当前场景，避免将全量事件池和内部标签送入模型。

### 9.3 P4 结局链
1. 年龄自然增长但不再因到龄结束；完成条件是同一已承诺主线完成伏笔、压力、高潮与回收，具有真实抉择后果，且不存在活跃矛盾。
2. 引擎写入 `mainlineCompleted` 后，普通候选和背景年份被阻断；模型工具集只剩 `request_story_closure`，不得开启或延续新主线。
3. 引擎审批请求后评估属性、天赋、道具、历史代价和路线 flags，锁定好/坏结局蓝图；随后渲染收束场景、完成结算并生成最终结局文本。
4. 结局工具调用缺失、格式错误或不可用时，运行态保持在结局引导，不推进无关年份，也不把内部协议错误投影给前端。迁移存档会在背景段落前刷新主线完成状态。

## 10. 路线局部节拍与世界幕（2026-08-21 01:29 +08:00，增量）

> 本节修正第 9 节中“活跃场景决定全局候选”的过时表述；不改写历史记录。

1. `NarrativeWorldDefinition.routeArcs` 是世界包拥有的完整路线目录。模型在 `propose_story_intent` 中从该目录选择 `routeId`；引擎不假定路线数量、名称或古代世界的六条路线。
2. `NarrativeRunState.routeProgress` 按路线分别记录 `setup -> escalation -> pressure -> climax` 的最近已结算拍点。事件自身保留 `narrativeBeat` 编码；引擎读取所选路线的局部进度，从该路线既有素材中选当前拍点的具体事件。
3. `activeScene` 只投影本回合所选路线的可见场景与年龄计时状态，不再是其他路线的候选门槛。模型切换路线时，未选路线的局部进度不丢失也不被自动推进。
4. `thread:*` 仍是事实账本和路线素材的关联信息。叙事候选不会因另一幕已回收同名路线事实而被排除；非叙事旧路径仍执行原始事实前置校验。
5. 任一路线走到 `payoff` 即完成当前世界幕。引擎写入该幕事实、推进 `mainlineActs`，并只重置实际达成 payoff 的路线进度；其余路线保留进度，继续在下一幕世界上下文中叙事。
6. 当前古代包配置三幕世界主线：旧案显形、阵营周旋、北境救国。三幕各完成一次 payoff 后，才沿用既有完整性、事实、抉择后果和模型 `request_story_closure` 审批链进入结算。

## 11. 属性策略、名望与三档结局（2026-08-22 01:34 +08:00，增量）

1. `NarrativeAttributePolicy` 是模型工具参数与引擎审批共用的共享契约，限定可影响属性、方向、幅度、数量以及是否必须包含正收益。模型负责选择符合叙事的语义后果，幅度仍由引擎稳定换算为 `light=1 / medium=2 / heavy=3` 并受年龄阶段上限、天赋减伤约束。
2. 普通背景段每年要求一项轻/中度正向成长；其模型调用次数保持不变。连续背景正收益仍受既有节奏抑制，避免普通年份压过关键抉择。
3. 导演抉择的三档策略为：`safe` 一项轻度正收益；`balanced` 一至两项轻/中度结果且至少一项正收益；`risky` 一至两项轻/中/重度结果，可形成突破或挫折。引擎拒绝不在策略范围内的工具参数。
4. `fame` 由属性加权基础、世界幕 payoff、稳健/适中抉择、冒险突破和冒险挫折共同计算，限制在配置的 `min/max` 区间。名望只作为结局质量的有限修正，不决定故事能否进入结局。
5. 主线完成和模型的 `request_story_closure` 仍是结局入口。引擎在入口后按路线蓝图、属性、历史抉择、天赋/道具、叙事挫折与名望锁定 `good / normal / bad`；渲染模型只能根据已锁定的品质与蓝图写结算文本。

## 12. 动态世界幕导演（2026-08-22 04:29 +08:00，增量）

> 本节取代第 9、10 节中“静态候选 + 路线局部节拍”为当前运行时的描述；旧节保留为变更历史。

1. 当前唯一的叙事导演模式由世界包提供 `mainlineActs`、`mainlineFacts`、`routeArcs` 与 `narrativeFactions`。引擎不认识“古代权谋”的具体含义，只读取世界包中声明的幕顺序、事实、路线和阵营 ID。
2. `NarrativeRunState.actRuntime` 是每个世界幕唯一的五拍状态：`setup -> escalation -> pressure -> climax -> payoff`。每拍模型都可从完整路线目录选择叙事视角；路线不是互斥分支，也不会成为下回合的候选门槛。
3. 模型调用 `compose_world_scene` 一次提交路线 ID、阵营 ID、人物提议、玩家可见正文，以及在压力/高潮拍点的三个抉择选项。引擎校验 ID，结算年龄、停表、属性、死亡、事实和幕推进；不再从静态 `EventDefinition` 中筛选候选事件。
4. 世界事实由引擎在 `setup` 引入、在中段触及、在 `climax` 的玩家抉择后按 `exposed / concealed / compromised / sacrificed` 之一收束；`payoff` 才记录该幕完成并切换下一幕。三幕事实完成后，既有模型结局申请和三档结局质量链才可开启。
5. 局内生成的 recurring 人物存入 `NarrativeRunState.dynamicCharacters`，并以 `PublicRunState.narrativeCharacters` 投影为“命运人物”；一次性路人只留在回合叙事，既不污染长期记忆也不复用道具语义。
6. `memoryEntries` 是单局本地记忆。检索按事实/路线/阵营精确匹配优先，再以文本词重合排序；它只为提示词提供少量已发生材料，不能选择路线、节拍、事件或结局。

## 13. 单次工具回合与成长缓冲（2026-08-23 +08:00，增量）

1. 活跃导演回合只调用一次 `compose_world_scene`。工具返回 `turnKind=scene | background`：背景段携带可变年份跨度、正文和逐年属性语义后果；场景段携带路线、阵营、人物、正文及按需生成的抉择。引擎根据工具结构结算，不再对背景做第二次模型渲染。
2. 引擎把完整世界路线目录交给模型。属性门槛只决定本回合工具 schema 是否允许 `scene`，不会筛除路线候选；setup 保持世界幕开场，payoff 不再受属性门槛阻断。
3. 普通人生段不携带路线、节拍或普通事件标签进入模型和前端。它仅受到年龄范围、既有对局上下文、基础安全规则与受控属性政策约束，允许平静成长、个人感受和幕间承接。
4. 每幕 setup 后会产生一项玩家可选的成长方向。选择保存于 `NarrativeActRuntime`，普通年份的属性政策要求至少一项效果命中该方向主属性；前端仅显示选项与属性档位，不展示内部世界幕或路线 ID。
5. `pressure` 与 `climax` 必须产生可渲染的三项抉择；`setup` 和 `escalation` 可以由模型在同一次工具调用中决定是否形成真正取舍。无抉择的场景依旧提交受控属性后果并推进一拍。

## 14. 生存、天赋与命运人物（2026-08-25 14:54 +08:00，增量）

> 本节取代此前关于动态工具名、静态事件候选和“命运道具”人物投影的过时描述；历史段落保留用于追踪演进。

1. 当前动态工具集是 `render_background_segment`、`render_scene` 与 `render_choice_scene`。模型在一次调用中选择当前路线与阵营视角，并提交玩家可见文本及受控结构；引擎不再从静态事件候选中为其选取具体事件。
2. 生存规则属于世界包 `progression.survival`。引擎只在实际跨过一年后，根据年龄阶段体魄风险线累计低体魄年份；达到宽限期后，以配置的阶段概率触发生存危机，而不是直接死亡。
3. 生存危机是一个独立的引擎等待态。玩家选择自愈、请求帮助或听天由命，分别使用智力、魅力、气运档位结算；高档必定成功，成功后体魄恢复至当前风险线加配置缓冲，失败才写入 `dead` 和确定性死因。死亡文本仍由模型在既有上下文上渲染，模型不可自行判死。
4. 天赋卡的数值修正仍在 `createRun` 时结算；仅玩家实际选择的 1 至 3 张卡会被压缩为叙事偏向、关联主题与风险取向，进入身世、动态场景和结局上下文。天赋卡不会把整个卡池或内部规则暴露给模型。
5. 模型新建并标记 `recurring=true` 的人物才进入 `dynamicCharacters`。后续再出场必须引用稳定 `characterRef`；引擎以该引用回填并维护姓名、阵营与身份。对于遗留的 `new` 引用，若姓名与阵营已存在则收敛到同一身份，避免“命运人物”出现重复投影。
