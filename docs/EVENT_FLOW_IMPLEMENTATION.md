# 人工事件骨架与本局具象化

本轮目标是让边镇线实际经历成长、入伍、统军和战争，并完成一局。先完成主线，再优化连续性维护。原有未提交改动保留；其他 IF 尚未编写事件骨架时保持现有运行方式。

边镇线新局使用运行版本 20，骨架与世界卡随存档固定；其他路线保持版本 18。版本 19 保留只读。组前准备和预设角色卡维护见 [版本 20 记录](EVENT_FLOW_V20.md)，最新独立收束、接组和分时段历史见 [2026-11-06 记录](PERIOD_MEMORY_AND_EVENT_ROUTING.md)；[版本 19 全链路验收](EVENT_FLOW_VERIFICATION.md) 保留为历史对照。

## 已确认

- 人工编写完整事件组、分支和出口；幕初模型依据本局世界卡具象化人物、地点和物品。
- 普通生活承担成长，完整大事件可以跨年。节点不是一句对话或一次手续。
- 选择和持久化掷点决定明确后续结果；普通失败可以改变路线，重大失败可以结束对局。
- 资产维护继续只供展示，不恢复召回，不以维护成功作为事件成立条件。
- 版本 20 严格只整理本批事件组的预设资产；身世身份从出生时登记，人物、地点、本领和道具分别维护简短状态，性质和方法取自人工素材。
- 成长组可配置关键属性准备条件；组前复用普通年份，达标后持久化准入，组内不再因属性下降打断。
- 道具的玩法所有权由事件结果提交；展示维护不能增删玩法库存。
- 仅使用 Material/ak.txt 的限额 key 实测，独立测试存储，不覆盖玩家局或输出凭据。

## 执行职责

- 人工素材按叙事地位组织可复用的事件组，组间不预写固定跳转树。幕初选出本幕候选组和开场组、具象化角色名称；当前组未结束不能抽取新组。
- 用户认可第二幕试点后，边镇线 13 组均使用 `routing=planned`，完整单元提交后由规划只返回本组下一单元 ID。不同胜负可接同一后续单元，实际历史保留进入该单元时的差异；规划不重述局势或裁定奖惩。军议按明确规则在同一次正文中提交适用规则及实际处置。组内必须有明确出口，存活决战结果先接战后处置与生活，战死结果直接交结局观察。旧顺序组快照不迁移。详见[试点](FRONTIER_CAMPAIGN_PILOT.md)与[推广记录](FRONTIER_EVENT_ROLLOUT.md)。
- 完整抉择裁定后落实所选行动与成败对应结果。组结束后由观察器只确认继续、换幕或整局结束；继续时由独立规划依据上一组结果选择后续组。候选不进入收束观察，两个结果分别保存。
- 节点指定核查属性和难度，沿用现有概率公式与单次持久化掷点。
- 正文明确交接同年或跨年；换组、换幕不覆盖这一交接，不设同年次数上限。
- 观察器确认整局结局时同时确认主角生死及必要死因，引擎保存并用于结局状态。
- 既有名称由引擎复用，幕初仅命名新角色；开场组的明确道具条件使用实际玩法库存核对，候选素材不代表取得。

## 实施与证据

1. 人工写通三幕事件组，包含普通成长、失败后续、道具交付和明确结局。验证每个结构出口可达，避免无限返回同一检定。
2. 将骨架与幕初绑定接入现有唯一世界卡生成入口；未执行分支不写入实际历史，正文仅取得当前节点或已选结果。
3. 接入当前提交、重试、求生与存档。推进游标和玩法库存是引擎状态，不是另一份叙事摘要。
4. 验证请求职责及缓存，执行回归与构建，再实跑完整对局；保存原始请求、返回、掷点与实际提交。
5. 分别报告可达性、实际故事质量、连续性展示质量。完整结局不能替代中途故事的审读。

固定职责、工具与幕初材料在前；当前节点、实际历史、年龄、库存和既定结果在动态材料中。不得按成败改写 system 或工具，不向正文倾倒未选择分支。
