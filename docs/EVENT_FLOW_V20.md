## 展示维护不再补写档案

固定工具 `sync_event_assets` 只有 `introductions` 与 `updates`，允许空数组。登记和状态可以在同批提交，先登记再应用；同一操作数组内不重复身份。引擎整批校验后发布，不部分写入。

| 对象 | 同步可写状态 | 固定内容 |
|---|---|---|
| 人物 | 健在、负伤、被俘、死亡、离场；与主角的关系 | 身份与性质取预设素材 |
| 地点 | 可用、受威胁、交战、受损、失守、荒废；是否当前所在地 | 性质取预设素材 |
| 本领 | 未学、入门、熟练、精通 | 本领的方法与性质取预设素材 |
| 道具 | 他人持有、本人持有、已交付、损坏、丢失、已消耗 | 性质取预设素材 |

各类均可退出展示；当前所在地保留最简身份。相同值不刷新变化时间。同步不接受 `description / usage / source`、经历、动态事实或额外资产。道具玩法库存仍只由实际事件结果更新，展示同步不能发放或消耗道具。前端复用原档案布局，本领与宝物统一标注“状态”。

维护 system：

> 对照新增实际对话，只整理本批候选中的预设资产。记录它们已经改变的现状；没有出现或没有变化的对象省略，不整理经过，不增加候选以外的资产。

身世的固定身份与后续状态分开。没有发生或不知道的状态可以保持空白，不为填满面板推测。
