## 实测发现并修正的交接问题

| 问题 | 修正与验证 |
|---|---|
| 组内第一个抉择结束即调用观察，误把未完组当作需要转组 | 只有组末或素材明确结束组才观察；组内普通提交前进节点，不抽新组 |
| 幕初可能选择需要尚未获得道具的开场组 | 输入实际库存；世界卡提交前检查开场组的明确道具条件。交付已发生后不再次要求被消耗道具仍在库存 |
| 观察工具未说明 `act_closed` 与整局结束的区别 | 四种决定含义明确写在固定工具中；首次入伍实际收束进入第二幕 |
| `next_flow` 被称为“继续”，证据说明却允许继续时省略，解析又要求证据 | 工具说明分别交代 ongoing、转组和收束的证据。末次真实回放一次返回转组及依据 |
| 换幕要求模型逐字重交已确定名称，产生多次名称顺序变化报错 | 只请求尚未绑定角色；引擎复用本幕所需的既有绑定。两种 provider 回归及真实回放验证名称保留 |
| 战死结果可能在通用结局提交时被覆盖 | 观察提交生死与死因；结局收尾保留实际死亡状态，回归和完整对局均已验证 |

末次幕初回放仍发生一次行动方漏字段纠正；随后通过。名称不再重交，但不能据此声称模型协议错误已经消失。
