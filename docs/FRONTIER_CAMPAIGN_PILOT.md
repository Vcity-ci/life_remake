# 边镇线单组试点：出击与成为将军

更新于 2026-11-06。本文保留第二幕 `border-campaign` 单组试点及原始实测。用户已确认“这个呈现方式可以接受”，后续推广见[全线材料记录](FRONTIER_EVENT_ROLLOUT.md)。

## 验收目标

玩家经历一支部伍从编练、实际接战到独立出击的变化，知道同伴为什么跟随、敌人怎样回应、胜负究竟改变了什么，以及授职依据是什么。一个单元只处理一件完整的事，其结果当次成立。后续规划依据这个结果接通下一单元，不能退回原问题重掷。

“通常承载三至五年的内容”用于衡量成长、行动与事后影响是否充分，不转成最短年份、最长年份、回合次数或观察器验收条件。紧迫战斗仍可以同年推进，重要后果可以延续多年。

## 一、按整条链路整理字段

| 层／字段 | 当前实际用途与冲突 | 取舍 |
| --- | --- | --- |
| `name / tagline / summary` | 选线展示；宣传文案不直接供应本局正文 | 保留展示职责，边镇内容与实际军旅主线一致 |
| `routePromise` | 同时进入路线脉络、当前视角和观察器；旧值还要求回答守护、割据、重塑秩序 | 不再作为重复的运行指令；本局发展由人物轨迹、当前幕目标及具体局势承担 |
| `protagonistTrajectory` | 主角在这条线中的长期成长 | 保留明确的身份与行动能力变化，不增加人生意义解释 |
| `coreOpposition / centralConflict` | 幕初同时供应两份近义对抗说明 | 运行时只供应一份持续冲突；具体对手、力量与主动行动在本幕主持资料中具象化 |
| `stakesProgression / endingQuestion` | 与三幕目标、利益及结局标准叠加成多层主题要求 | 作者构思与实际验收分开；不再把哲学提问供应为观察器必须回答的结果 |
| `stakeAxes` | 加载校验需要，当前没有独立运行消费 | 不增加追踪台账；不因为字段存在就要求正文逐项表达 |
| IF `acts[].objective` | 本幕方向 | 保留；不是当前节点的任务清单 |
| IF `payoffMeaning → closureMeaning` | 观察器的整幕收束依据 | 保留唯一来源，正文不接收详细判据；局部事件的结束不等于整幕结束 |
| IF `endingDirections` | 观察及结局都接收；旧的战争／互市与消除猜忌使等级边界交叠 | 标准描述实际战局、军民与事业结果；互市不再是默认好结局要求；残留猜忌本身不否定已经成立的胜利 |
| `worldCore / storyBible / 静态资料卡` | 世界事实、开局局势、制度和行动条件 | 保留适用事实；欠饷、互市等背景不自动变成每局待办 |
| 幕卡 `actors / locations / pressures / stakes` | 行动方、空间、世界主动发展、利害 | 各自保留；不把同一件历史损失分别改写成多份待证明义务 |
| `flowBindings` | 同一预设角色在本局的名称 | 名称绑定不表示已经登场、取得道具或形成未来关系；与主持资料中的具体人物承接 |
| 组 `entry / narrativeRole / preparation` | 入组适用性、整幕地位、未入组时的生活 | 分开：适用性不预写本组全部经历；准备不抢写组内战果；叙事地位不另添收束标准 |
| 节点 `situation / outcome.result` | 已选场景与确定结果 | 起点交代行动条件；结果交代实际变化，不在一个生活节点里提前完成整场战役 |
| 选择 `action / success / failure` | 玩家办法、引擎已确定成败后的结果 | 未选分支不进入正文；后续承接所选结果，不重新裁定同一件事 |
| 展示资产 | 预设人物、地点、本领、道具状态 | 继续只供前端，不恢复召回，不承担推进证明 |
| 时段摘要与未覆盖正文 | 实际历史唯一供应 | 保持现有入口，不生成本组进度摘要或另一份人生解释 |
| 结局 | 对整局已发生人生的评价 | 明确是本局总结；不继续最近一场戏，不补办未发生的互市、问责与授职 |

字段定义、最终消息组装、静态资料和实际生成文本要一同核对。删除一处文字而从另一个栏目重新供应，不算完成。

## 二、修改前的具体缺口

修改前只有 `campaign-formation → campaign-raid → general-commission`。

- `campaign-formation` 是一个生活节点，却预先完成合编、任用骨干、演练、迎击敌骑、攻取据点；重要成长被挤成一句战果概述。
- 组内提交只执行 `eventIndex + 1`，没有独立接通。攻营失败后，只要没有战死，仍直接进入同一授职节点。伤亡有变化，主角的立场、可用力量和取得职责的依据没有进入下一单元。
- 授职节点同时写正式任职、接兵、布防和部属关系，缺少玩家亲历的前置过程。
- 幕初目录只提供节点 `kind / situation`，没有完整交代该组可形成的变化及失败后续；组织本幕时看不到完整的素材职责。
- 正文只取得当前节点；应补足本组稳定的局势与相关行动方，不向正文倾倒未来成败分支。

## 三、试点单元与接通分工

沿用现有军镇、关城、河谷、伙伴、邻军偏将、敌方游骑与边外营垒。不引入欠饷冲突等另一条剧情，不靠新增资产数量表现丰富度。

| 经历 | 玩家实际读到的发展 | 对后续的实质作用 |
| --- | --- | --- |
| 接兵与编练 | 原小队骨干接过队官职责；邻堡兵有各自旧习，枪盾、弓弩、骑哨通过共同操练形成协作 | 主角取得的真实部伍与同伴职责清楚，能力增长有使用场景 |
| 初次合军接战 | 用新编队伍迎击既有敌骑，邻军有自己的判断和行动；本次战果或损失当次裁定 | 后续处理已经成立的敌我处境，不把失利改写成仍待重试 |
| 部伍调整 | 根据上一场实战处置实际的协作问题，调整骨干职责与训练方法 | 同一单元承接胜败，但调整的原因、主角的权限和可用部众不同 |
| 攻营关键取舍 | 沿用三档行动与持久化掷点；本次所选目标当次裁定 | 胜利与失利产生明确不同的敌我处境 |
| 战后生活与部伍变化 | 依据实际分支处理伤亡、伤者职责、补员、伙伴关系及战利品，已经结束的作战不重新开启 | 收获与损失留下来，而非只有一段结果文案 |
| 军议任职 | 镇将按实际编练、战果与失误，依明确规则授偏将、留任校尉或降任队正 | 不无条件授偏将，不为一次失利另建必经补考；任职与道具所得必须一致 |

普通生活可以承载季节、操练、关系与恢复；战斗按实际局势连续进行。事后收获与损失属于已发生故事，不增加维护模型的扩写任务。

人工素材定义单元的起点、处理的事情及适用条件。上一单元提交后，`route_event_unit` 依据实际历史，从本组未完成候选中只返回 `nextEventId`。规划不重述立场、改写局势或裁定奖惩；正文通过同一份实际历史承接胜负、伤亡、权限与可用部众。不同结果可以接回同一个单元，正文不接收未来未选分支。

军议为 `kind=settlement`，三条规则分别定义适用事实与处置：实际练成多队并有成建制作战成果，授偏将并交将旗；仍能带队但成果不足，留任校尉；严重失误已导致多队溃散或失去指挥权，降任队正。一次普通失利不自动触发降职。正文在同一次生成中提交适用的 `resolutionId`，写完该处置；引擎按规则 ID 校验、提交库存及组结果。规划不选择处置，也不再增加一次奖惩评判请求。

试点组标记 `routing=planned`；只有明确的 `endsFlow` 结束本组。试点验收前其他组仍沿用原顺序；用户认可后，边镇线其余组才按相同分工推广，旧快照保留原材料与执行方式。

## 四、已经实施的字段取舍

- 幕初路线供应收敛为人物成长、持续冲突与幕目标；`routePromise / coreOpposition / stakesProgression / endingQuestion` 不再叠加为运行指令。作者字段尚未删除，不宣称已经清理全部配置。
- 使用 IF 时不再同时供应通用世界的主线骨架。
- 观察器取得人物成长方向、实际历史和 IF 结局标准；不再追加另一份主题提问。
- 边镇结局标准按已经落定的战局、军民与军旅事业区分。互市不再是好结局的默认任务；残留外敌或猜忌不单独否定胜利。
- 结局渲染取得已确认等级、实际结果依据与完整历史，不重复供应用于裁级的全部候选标准，不追加“最新已提交处境”标记。结束年龄不再表述为人生终点。结局不接收面向继续行动的当前能力与学习方式，也不再供应重复的最终属性数值；前端数值与已确认等级不变。
- `routePromise / coreOpposition / stakesProgression / endingQuestion` 仍保留作者字段和部分旧解析投影；本次清理的是当前 AI 请求中的叠加供应，不宣称已全局删除这些字段。
- 已完成请求供应、历史、路由和军议回归，以及隔离新局试点。结局在后续验证中恢复为简短总结，实际样本见第八节；故事质量仍须玩家审读，不由机制测试代替。

## 五、实现与验证顺序

1. 完成字段供应取舍与具体内容对齐；记录实际变更，保留未修改项。
2. 接通一个组的完整材料与分支承接，复用现有提交、掷点、库存、时间与求生入口。组内新增独立路由调用；军议在原正文调用内处理规则，没有额外奖惩请求。
3. 规则验证覆盖组内持续执行、未选内容隔离、失败后不同处境、保存恢复和固定前缀。
4. 使用已授权 `Material/ak.txt` 限额 key，在隔离存储实际运行试点；保存原始请求、返回、实际提交与可阅读故事，不覆盖玩家局。
5. 向用户展示完整故事及与修改前的差异，依据反馈继续调整；未经用户满意验收，不扩写其余边镇事件组。

试点通过的依据是实际经历有内容、人物与敌我处境持续改变、成败得到承接。类型检查与完整结局可达各自只能证明其覆盖范围。

## 七、仍需验收的不足

1. 试点正文仍有“写进册子、照名字认人、阿禾记册”等细节。实战与后果已经展开，但旧的清点意象尚未消失。本次没有通过关键词过滤掩盖它们。
2. 试点之前的旧组出现一次展示维护错误 `event_asset_not_registered`；已提交故事继续保留，后续维护机会接着处理。整局并非零错误，其他组也尚未按试点颗粒度更新。
3. 幕卡仍有把出生年号留作当前开幕年份的产出；真实历史已经到青年，稳定设定与当前时间的表达仍需分清。这不是本次路由成功已经解决的问题。
4. 军议正文同时写“偏将站在镇将右侧”和“郭戍立在对面”，而郭戍本身就是邻军偏将，存在身份表述混淆。已保留原文供审读，没有修改公开文本。
5. 结局仍会沿用实际历史中的旧水囊、名册与清点意象。缩短总结不能替代这些内容来源的审查；不能根据一段总结已变短就宣称整局叙事偏移全部解决。

2026-11-06 用户审读后确认“这个呈现方式可以接受”，推广条件已满足。上述旧局问题保留，不因推广抹去；全线叙事效果另行实测。

## 八、继续核对结局后的改动与实测

第一次回放 `storage/verification-ending-retrospective-20261106/comparison.md` 返回约 2,400 字。检查实际请求发现：

- 固定职责新增了“贯通身世、成长、关键抉择与最终结果”的逐项要求，反而邀请模型编年复述。现替换为单一职责：“用一段简短的文字总结并评价本局人生。”
- 结局仍接收“你目前……、你的能力基础……、你的学习与行动方式……”，又接收最终属性与名望数值。它们原为下一段行动准备，不再供应结局；稳定人设、实际历史、已确认等级、结束年龄与结果依据保留。其他请求继续正常取得当前状态。
- 没有删除、另写或截断实际历史，没有增加结局提要、二次改写或额外审核请求。固定职责不随等级改变，动态结果仍在后。
