所有组使用已有 `routing=planned`：规划只返回下一单元 ID；本组未结束不抽取新组。材料加载校验组内有明确出口，避免耗尽候选仍不能完成。它不判断语义结果或固定经过哪些单元。

决战结果只裁定军事行动，不在同一分支顺带完成军议和军民安置。存活且战争已停的结果接入同一军议，正文在原请求中选择适用规则、写出实际处置；引擎校验规则身份。战争仍在的败退接最后防线，死亡不进入存活者的生活。整组实际完成后，观察器再依 IF 标准判断整局。

## 实测发现后的材料修正

1. 第一局“合军坚守成功”实际写成献城撤民。原请求已经有成功结果，模型仍改写了目标。本次将结果具体落到敌军退离城下、守军继续控制城门与城墙；定点回放已保有要塞。后续军议中的“新防线”又容易暗示搬离现有城池，改为实际守住的城堡、地域与已确定驻地；这项末次措辞收紧尚未再作模型回放。
2. 第二局救援全员返回，安顿材料却无条件要求面对死者亲属、缺员，正文于是新增死亡，再接重整。去掉事后单元预设的伤亡，安顿只处理归来者的生活；部众与物资沿用既定得失。重整入口收紧为实际失编或协作破裂，普通休整由前组承担。定点回放未新增死者，也未误接重整。
3. 相同问题存在于试点出击后的归营文字：无条件出现伤者、战死者家属与补入者。保留已认可的单元与军议结构，仅将这些内容改为按已提交的战果、部众和物资处理归营；不预设每次出击必定死人。
4. 家庭成长、被俘归来和战后生活涉及原有父母身份，候选范围补入这些既有角色，避免正文写到家庭变化，展示维护却无权处理对应预设角色。没有新增资产类型或让展示内容反馈正文。

定点回放的 `NARRATIVE_CHECK_CURRENT_MATERIAL=1` 只为隔离开发样本换用当前作者材料，沿用已知绑定与已提交正文。原始存档不变，生产读档仍保留原快照。这不是旧局自动迁移。首次最后防线回放因测试夹具未补齐既有家庭绑定而失败，记录保留在 `storage/verification-frontier-last-defense-20261106/`；修正工具后在独立目录重跑。
