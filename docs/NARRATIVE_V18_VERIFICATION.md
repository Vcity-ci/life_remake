## 实际模型测试方法与记录

入口：`scripts/live-narrative-check.mjs`。独立临时工作目录和匿名会话，不覆盖玩家运行存档或自定义配置。key 只在内存传给配置入口，捕获文件不记录请求头。选择采用正常选项及真实持久化掷点，不改年龄、骰值、故事结果或观察决定。

首次实跑在选项本领引用上阻塞，修正协议后重新开局。后续从测试保存点继续，保持实际正文、卡片、年龄和掷点；续跑不是清洗存档。

主要材料位于 Git 忽略的以下目录：

- `storage/verification-1793794216612`：首次选项绑定错误。
- `storage/verification-1793794770742`：从出生开始的 100 次操作测试；最终未结局。
- `storage/verification-1793796053795`：保存点续跑，暴露新地点与活动交接错误。
- `storage/verification-1793796442919`：再次续跑，暴露名称被当成未知 ID 的错误。
- `storage/verification-1793796747285`：续跑至二十四岁、192 条公开记录，仍在第二幕；暴露展示归并后的旧名称活动校验错误。
- `storage/verification-1793798059008`：从该失败点回放三次正常操作，正文、抉择及结果均提交，最后推进到二十五岁、195 条记录；仅因三次测试预算停止，没有再出现活动名称校验错误。

每个 `model-*.json` 保存实际发送的消息、工具、原始模型返回、用量和耗时。`latest-run.json` 是测试内部状态；`verification-result.json` 记录该次测试的最终状态。旧批次保留其当时协议，不能拿它的字段当作最终代码仍在发送的字段。

最后一次长续跑进一步证实：只删除提示词目录还不够。展示同步归并“西岭关马道口”后，历史里合法存在的原名称不再精确匹配当前目录，导致活动提交被拒。本轮已统一修正人物、地点、本领的名称解析和活动登记：目录只决定能否复用身份，不决定正文名称是否有效。不能唯一识别时建立候选，交由展示维护判断同一性；不做别名猜测。伪造 ID 的拒绝与单次纠正测试保留。

## 故事实际发展与未通过项

从出生开始的测试写了边地军户家庭、后山探险和斥候线索，随后大量停留在报话、记雾录、查箭捆、核名册和官署问话。八岁阶段连续出现许多细小同年段落。后来写到“半名额、入营跟班听用”，观察器将实际哨务判为入伍并结束第一幕；第二幕准备完成后，主角二十岁率临时小队接回二十三户迁民与两名失散兵卒。救援成功、军功成立后，正文又转向送图、查经手人、抄本与官署核问。

第一幕能结束，验证了换幕交接；但 `model-0277.json` 用“半个名额、入营跟班听用”证明“实际入伍”，尚不能据此宣布正式入伍标准已严格落实。第二幕没有凭一次救援自动结束；故事仍没有持续展开训练、出击及统军成长。这些实际判断与发展均不能宣布通过。

### 1. 切断资产后，局部细节拖延仍然存在

本次测试没有幕内召回请求。真实普通场景返回中，83 次调用有 77 次明确提交 `hold`，6 次提交 `advance`（含纠正调用）。因此这批同年停留来自模型的明确时间交接，不能归咎于引擎把跨年结果改成同年；也不能通过恢复默认跨年掩盖问题。

例如主测试 `model-0123.json` 已使用干净主持职责，但收到此前大量局部历史后仍继续官舍问答。续跑 `verification-1793796747285/model-0097.json` 的完整请求中，system 为主持及第二人称职责，当前任务只有年龄、120—220 字建议及核查属性；实际返回仍从偏院问话停到下一句反问，并提交 `hold`。同时两种正文工具均开放，`tool_choice=required`，不是引擎强迫它选普通场景而封锁抉择。

续跑后来由模型明确提交 `advance`，年龄实际从二十进入二十一、二十二、二十三；随后又停留在绳扣和册子。这验证时间交接能够跨年，也说明跨年本身不等于故事取得相应发展。此时资产维护没有回流，仍有实际历史对局部题材的持续强化，以及世界卡中的同类压力与材料。这里记录已发生现象，不把某一个输入擅自认定为全部原因。

这份历史没有通过资产重复供应，但正式压缩文本仍保留雾录、叉记、画押、绳扣和逐岁经历。第二幕固定起始资料也保留“十岁”“半名额”与官署问责，而实际执行已到二十岁以后。最终请求同时包含这些材料与后来的实际历史；清除目录回流并没有自动清除历史及起始材料中的注意力牵引。本轮按边界保留压缩职责和世界卡机制，未把这些实际产出问题改写成已解决。

### 2. 展示维护质量仍不合格

主测试快照中有 17 名人物、26 处地点、20 项本领和 58 条事项，其中 32 条仍开放。同步实际执行了归并和撤下，但没有把档案收束到足够简洁。

真实返回仍出现：把“自行重抄册子并保管”再立为承诺；人物关系重述递话和劝说经过；设施状态记录谁问了谁、谁说了什么。它们违反现状字段的职责。接口支持差量和撤下，并不代表模型已经正确使用它们。

主测试中连续性同步 42 次实际调用，输出 55,770 token，9 次为纠正；普通场景 83 次调用，输出 30,007 token。数字包含纠正的实际成本。同步仍明显过重，前台仍等待其处理；本轮没有以后台化或截断掩盖这一结果。

最后三次回放后的保存状态为 29 名人物、32 处地点、38 项本领、114 条事项，其中 50 条开放。它们已经隔离为展示资料，但数量和内容质量仍未达到“先把整理做好”的验收目标，召回不能恢复。

`model-0329.json` 与 `model-0330.json` 显示，最终 schema 已使用条目差量，但模型仍提交旧 `features` 整组字段。纠正后仍保留一个旧字段，整批未应用；服务器记录失败，故事提交继续，失败批次保留。这验证了失败隔离，也证明真实协议遵循和档案质量尚未合格。

### 3. 完整对局验收尚未通过

从出生开始的 100 次操作测试没有结局，停在第二幕；后续长续跑到二十四岁也仍在第二幕，并在展示归并名称校验处阻塞。修复后的三次回放恢复提交并到达二十五岁，完整对局仍未结束。回归中的提前败局、最终结局与求生恢复成立，不能代替这次真实对局的完整结束。

## 结论边界

本轮已验证：第二人称恢复；资产回流切断；观察未压缩历史补齐；边镇目标校正；登记协议与最终请求协调；维护失败不再阻断已提交故事。
