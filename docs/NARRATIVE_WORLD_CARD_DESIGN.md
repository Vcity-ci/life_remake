# 叙事世界卡与情景记忆设计基线

更新时间：2026-09-21 +08:00

## 2026-09-21：v10 基础世界与 IF 子世界包

本轮将“世界是什么”与“这一生要走哪条路”拆成两个独立内容层。下方 v9 章节保留为演进记录；与本节冲突时，以 v10 为准。

### 当前唯一运行结构

1. 基础世界包 `data/narratives/<worldId>.story.json` 只保存 `worldCore`、`socialForces`、`narrativePalette`、通用 `worldCards`、成长、生存和世界级三档结局。它不再声明 `storyPatterns`、`mainlineSkeleton` 或 `mainlineActs`。
2. IF 子世界包位于 `data/narratives/story-packs/**/*.json`，以自身 `worldId` 归属基础世界。基础世界不维护子包列表或固定数量。
3. 玩家先选择世界，再选择该世界下一条具体人生路线。子世界包提供路线承诺、入口视角、三幕目标、关键 stakes 与好／普通／坏路线方向。
4. 后端在新局开始时组合基础世界与选定路线，将路线三幕投影为现有五拍状态机使用的三个 `mainlineActs`。Horizon、Planner、Renderer、Beat Observer、事实、人物、地点、本领、死亡与结局状态机继续复用。
5. 选中的子世界包完整快照进运行态和存档。磁盘内容更新只影响新局；恢复旧存档不会中途替换路线。

### 独立创作合同

- 新增、删除或修改一条 IF 线，只操作一份子世界包 JSON，不修改基础世界、其他路线、前端枚举或引擎代码。
- 子包必须拥有稳定 `id` 与 `revision`，恰好三幕，且幕 ID 以子包 ID 为命名空间。
- `focusForceIds` 只引用基础世界已经声明的力量；它表示优先相关，不排斥叙事按需使用其他世界力量。
- 路线通过包级或幕级 `worldCardRefs` 引用基础世界卡；引用只调整召回优先级，不携带或复制卡片正文。
- 路线定义长期目标和阶段性戏剧问题，不穷举固定 NPC、地点、每拍事件或必然结果；这些仍由人设、已发生事实和局内动态资产生成。
- 没有任何有效子世界包的世界不进入可开局状态，不回退到旧自由故事形态。

三个内置世界均已迁移为 v10 基础世界。古代提供布衣逐鹿、庙堂权臣、边镇将帅、商贾世家、江湖宗师、方术教门；现代提供学途成章、事业造物、相伴此生、城中远行、众声之间、人生重启；奇幻提供宗门问道、禁区行者、散修天路、异族盟约、仙城争衡、逆命改天。

## v9 当前设计基线

世界包不再提供玩家必须选择的路线目录。它回答四个问题：这个世界是什么、哪些社会力量会行动、这里常见哪些叙事质感、哪些故事形态可供本轮借用。人物一生真正要讲什么，在身世完成后由玩家人设、最终天赋、身世和 `worldCore` 共同生成本局 `sessionPremise`。

当前内容层为：

1. `worldCore`：少量常驻世界规律，不包含已发生事件。
2. `socialForces`：可能产生人物、资源和压力的社会力量，不是互斥阵营选项。
3. `narrativePalette`：该世界的生活、冲突、行动与反思词汇。
4. `storyPatterns`：Planner 可选 0—2 项的故事形态；可复用、可组合，也可以本轮不选。
5. `worldCards`：按当前情景激活的制度、空间、文化、能力、冲突土壤与短表达样例。
6. 本局动态状态：人物、关系、地点、本领、事实、Episode、Act Canon、Digest 与 `sessionPremise`。

三个 `mainlineActs` 只提供长期叙事完整性的结构槽，不为世界包作者预写案件、求职、宗门试炼或战争顺序。五拍仍由引擎维护；独立 Beat Observer 只依据已经生成的正文判断当前拍应 `hold` 还是 `advance`，不能创造剧情或越权修改状态。

世界卡的关键词、Sticky、Cooldown、互斥组和预算规则继续有效。旧 route scope 说明仅适用于早期包；v9 内置包以任务、拍点、关键词和局内对象为主要召回条件。下方 v8 章节保留作为世界卡生命周期的实现历史。

本文件记录当前唯一叙事模式的产品目标与内容规范。它不是第二套运行模式，也不取代幕间、五节拍、路线、属性、死亡和结局状态机。

## 产品循环

引擎维护年龄、属性、世界幕、当前节拍、全部可选路线与已经发生的事实。叙事 Agent 从当前人物经历和世界包中召回相关素材，自由形成具体场景。玩家选择产生属性、关系、地点、本领与事实变化；任一路线完成当前幕的 payoff 后进入下一幕，三幕完成后才允许申请结局。

六条路线始终是模型可选的叙事视角，不是六条互斥主线。世界卡描述世界如何运作以及人物可以接触什么，不宣称某件本局事件已经发生。

## 统一内容层

1. 世界核心：少量常驻的世界规律与语言基调。
2. 主线场景：当前世界幕的戏剧领域和五节拍变化方向，不预设具体事件。
3. 世界卡：人物、地点、组织、文化、能力、矛盾土壤、后果与意象，按情景激活。
4. 本局动态卡：模型在本局生成的人物、地点、本领、关系与事实，以稳定 ID 持久化。
5. 风格示例：按任务召回的短篇幅样例，承担“怎样写”，不承担“必须写什么”。
6. 结局材料：只投影人生主题、三幕成果、重要关系、主要代价和属性定质。

## 世界卡写作规范

- `content` 必须脱离标题和激活键仍能独立理解。
- 优先描述空间、制度、资源、人物立场、生活方式、行动入口和后果，不堆砌“应当/不要”。
- `conflict` 描述能够生长矛盾的环境，不规定本局固定事件与结果。
- `consequence` 描述一类行动在世界中的反馈，不替代本局事实账本。
- `style_example` 只锚定观察距离、语言、动作密度、篇幅和收束方式，不携带必须复刻的专名或情节。
- route 卡只改变观察角度；所有世界配置的 route ID 每轮仍完整开放给规划模型。
- 已发生内容进入本局动态状态，不能反写为世界通则。

## 情景召回顺序

每次请求使用同一个 Scene Query：任务、世界幕、节拍、路线、阵营、年龄范围、当前人物、地点、本领、活跃事实、最近真实叙事、最近选择和场景目标。

召回按以下顺序进行：

1. 当前状态精确引用；
2. 最近叙事与场景目标的关键词/二级关键词匹配；
3. 已激活卡的一层关联召回；
4. 大型世界包可选的语义补充召回。

排序优先当前动态对象、幕与节拍、精确关系、关键词、关联卡，最后才是通用卡。互斥组只保留最相关的一张。Sticky 维持连续场景，Cooldown 防止同一提示隔轮反复成为中心。

世界卡只参与 `background / planning / horizon / rendering / dynamic / decision` 六类会实际消费世界资料的任务。身世、记忆整理、正文审校、结局审批与最终结算使用各自的专用材料，不隐式召回世界卡。

### Sticky 与 Cooldown 生命周期

- `stickyTurns` 表示首次直接命中或关联命中之后，额外延续的已提交回合数；`0` 不延续。
- Sticky 只跳过关键词再次命中，仍须满足 task、世界幕、节拍、路线、阵营、事实、人物、地点与本领作用域。
- Sticky 延续不算新激活，不刷新自身期限，也不再次扩散关联卡。
- Sticky 结束后才进入 `cooldownTurns`；冷却期间直接命中和关联命中都不能重新激活。
- 被互斥组、卡片数或字符预算淘汰的卡片没有进入最终请求，因此不会写入激活状态。
- Context trace 仅在后端记录激活种类、最近激活序号、剩余 Sticky/Cooldown 与排除原因，不投影给玩家或模型。

v8 世界包以 `worldCards` 作为唯一的静态召回来源，且必须至少提供一张卡；`lore` 保留为空数组。v1—v7 世界包继续读取旧 `lore`，两条内容链不会在同一世界包中并行竞争。

## Prompt 分层

从稳定到临时依次为：通用 Agent 契约、世界核心、主角身份与身世、当前幕与节拍、当前场景状态、动态人物/地点/本领/事实、召回世界卡、相关 episode、最近真实叙事、任务风格示例、当前场景目标、本轮请求。

同一来源由稳定 `sourceId` 去重。长期摘要只保存当前身份、处境、幕、主要关系、核心矛盾、不可逆变化和未兑现承诺，不保存完整编年史。

## 工具边界

模型负责路线选择、场景构造、自然语言、属性方向与幅度、以及从已经写出的叙事中提出状态变化。引擎校验 JSON、引用、数值档位与合法状态迁移，不审核文学方向。内部工具参数不进入玩家前端。

## 世界包验收

- 同一幕可以从不同身份、地点、人物与路线进入。
- 已解决的事件保留后果但退出待解中心。
- 动态人物、地点和本领能在相关情景自然回归。
- 三个世界在隐藏名称后仍能从社会运行、冲突和语言质感上区分。
- 上下文和工具目录不随存档时长线性增长。
- 世界包作者可通过 JSON 扩充可游玩世界，无需修改引擎。
## 2026-09-22：世界资料的三层权责

1. 基础世界稳定层回答“世界共同遵循什么、此刻正在发生什么”：`worldCore` 保存长期规律，`storyBible` 保存时代切片，`socialForces` 保存可行动的力量目录。
2. World Card 回答“当前情景需要知道世界的哪一小部分”：资料位于 `data/narratives/world-cards/<worldId>/`，可按制度、地域、阵营、人物、文化、能力、冲突和表达样例拆文件维护。
3. IF 子世界包回答“玩家选择用怎样的一生串联这个世界”：它持有路线承诺与三幕演化脉络，只通过 `worldCardRefs` 引用世界资料，不复制公共背景。
4. 世界卡引用是召回偏好，不是剧情白名单。Planner 仍可从本轮按情景初筛出的其他卡片中选择，模型选择的卡片通过既有 `focusRefs` 精确进入渲染上下文。
5. 世界已知人物和地点是“可能遇见的设定”；只有正文真正使用并经连续性提交后，才会进入局内命运人物、足迹或事实档案。这样既可复用世界人物，也不会把未发生内容伪装成存档事实。
