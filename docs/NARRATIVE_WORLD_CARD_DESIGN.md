# 静态世界资料与幕间主持资料

更新时间：2026-11-06。基础世界内容版本为 10；边镇事件组路线使用运行版本 20，其他路线保留既有入口。运行交接见 [当前架构](ARCHITECTURE.md)、[独立收束与接组](PERIOD_MEMORY_AND_EVENT_ROUTING.md)、[事件组规范](EVENT_FLOW_V20.md) 与 [运行版本 18](NARRATIVE_V18.md)。

本文件只维护当前内容职责。已退出的五拍、风格样例、人生提要和多路线轮流推进等旧设计不再作为制作步骤；历史可从 Git 查看。

## 内容放在哪里

| 内容 | 来源 | 职责 |
| --- | --- | --- |
| 共同设定 | data/narratives/<worldId>.story.json 的 worldCore | 时代、地域、制度与生活事实 |
| 开局时代局势 | 同文件的 storyBible | 起始时各地存在的主要局势，不作为永久“现在” |
| 力量目录 | 同文件的 socialForces | 阵营、阶层和组织类别，供路线引用 |
| 局部资料卡 | data/narratives/world-cards/<worldId>/**/*.json | 地理、机构、人物立场、文化与行动知识 |
| IF 人生方向 | data/narratives/story-packs/**/*.json | 入口、三幕目标、实际收束依据与结局标准 |
| 人工事件骨架 | data/narratives/event-flows/*.json | 已配置路线的完整事件组、选择、既定结果与预设身份 |
| 本局主持资料 | 幕初生成并保存的世界卡 | 选定的局势、具名行动方、地点、压力、利益、本幕方向及引擎保存的适用规则原文 |
| 实际经历 | 已提交正文、玩家选择和结果 | 本局已经发生的唯一历史来源 |

基础世界不登记 IF 数量，不复制各路线事件。IF 通过 worldCardRefs 引用公共资料，引用是材料偏好，不是剧情白名单。具名世界人物属于设定；本局是否遇见、拥有什么以及关系怎样改变，以实际历史为准。

## 静态资料写什么

worldCore 的 identity、powerStructure、everydayLife 保存已有设定事实。laws 为可选字符串数组，保存确实适用于全世界的简短规则；未配置时不输出“世界规律”栏目。不能为了填字段生成“资源决定权力”“做事需要认可”等普遍判断，也不把全部领域制度塞进全局 laws。

世界存在与世界规则分开：军镇、书院、行会的存在交代舞台；谁能授职、所得身份能调动什么、怎样取得和失去资源，才说明实际运行秩序。规则可以是社会制度，也可以是超自然规律；不要求稀奇，也不写成主角必须完成的剧情步骤。人生老病死等普通常识不需要包装成专门规则。

storyBible 提供开局时代切片。具体人物目标放入人物或势力卡，具体地理放入地域卡，不在总览重抄完整卡片。

每张资料卡只承担自身知识职责。机构卡说明职司、成员及适用范围；地理卡说明已知空间与条件；军事卡说明方法和条件。当地已有的借贷、军饷、官署手续可以保留在相关知识中，不因此成为全世界的常驻解释。

可独立引用的制度卡使用 kind=world_rule；按需选材使用 contextRole=knowledge，不能为了常驻而把所有制度设为 foundation。已确认的大衍 A—F 分别覆盖军职与军功、任官、行会与特许、师承、共同资产和教门公产。它们给出身份与实际权限的联系，不增加固定战斗次数、认可考验或引擎判定。

卡片不布置作者任务，不规定“人物必须判断什么”，不要求每次胜利后另起疑问、责任或手续。已经在其他卡表达的细节应归回适当来源，不能靠反复列举提高叙事权重。

本轮古代卡的处置及未解决问题见 [逐卡审计](ANCIENT_STATIC_CONTENT_REVIEW.md)。

## 当前实际供应

身世与幕初规划通过现有世界材料入口取得共同设定、开局局势及匹配的静态卡。边镇路线的幕初规划额外取得人工事件组目录和名称绑定角色；不再同时供应 IF 的另一套 adventureSeeds。

边镇幕初模型选出本幕可用事件组和开场组，组织 situation、actors、locations、pressures、stakes；objective 和 closureMeaning 取自 IF。世界卡整幕固定，后来的变化由实际历史承接。

幕初请求中，候选规则原文位于稳定世界设定，目录只列 ID 和标题。模型通过 worldRuleRefs 选择适用规则；引擎只接受本次实际供应且 kind=world_rule 的引用，并将对应 id、title、text 保存为幕卡 worldRules。模型不重抄规则，不从未供应的全库补取。

准备生活、剧情正文、抉择结果和观察器通过现有 actWorld 稳定材料读取保存的规则原文一次。正文不逐轮重新匹配规则，也不从展示资产取得制度。旧幕卡没有 worldRules 时保持原状，不自动生成、补写或改造；新幕生成才采用新规则选取。

事件正文与选择结果只取得当前节点或已选结果，并沿用本幕主持资料。不能把未来分支当成已经发生的事实。当前组未结束不抽新组；组末观察只判断本幕或整局收束，继续时由独立规划依据实际结果选择后续组。候选为空不转化为收束要求。

边镇展示维护只整理预设角色卡，不回流正文、幕初选材或结局；不能用展示资产回流解释已隔离后的重复叙事。其他路线的材料入口以其实际实现为准。

普通准备仍受属性条件与增益影响。增加世界文字不会自动缩短准备跨度，不能把内容整理当成数值问题已经修复。

## 引用与元数据

保留稳定卡片 ID、contextRole、任务、关键词与关联引用。删除卡片时同时清理相关引用；没有关联变化时不为清理正文而调整匹配算法、优先级或冷却。

origin 是可用的卡片任务，身世仍须满足各卡的任务与相关性条件。规则卡的稳定供应位置不会绕过选材范围。各 IF 可以通过既有 worldCardRefs 提高相关制度的选材相关性，最终本幕选择仍由模型完成。

现有匹配只决定什么材料进入请求，不能代替模型对故事意义的判断。扩大地理或危机题材，需要确认具体内容及真实消费入口，不能仅向某个未消费的字段追加文本。

## 缓存与历史边界

固定职责与工具、本幕稳定主持资料在前；实际历史、年龄、当前状态和本段节点在后。静态内容修订会改变相应材料一次，动态状态不得反向改写 system 或工具定义。

清理旧资料应修改其配置来源与供应入口，不将删掉的指导移到 user、工具说明或其他标题。实际正文、摘要、已生成世界卡和回合快照不因静态清理而改写。

## 制作与核对

1. 完整阅读现有材料，记录字段来源、真实消费者及具体重复。
2. 区分整理已有事实与新增剧情；新增角色、设定、危机或分支须先确认。
3. 删除空泛或越权指导，保留有效方法和已知世界事实。
4. 成组核对工具、字段、加载与最终消息，不用示例文本代替真实入口。
5. 检查 JSON、ID 与引用；按当次授权决定类型检查、测试和实际模型验证。
6. 实际产出未验证时，只报告完成了内容与供应清理，不宣称循环已经解决。
