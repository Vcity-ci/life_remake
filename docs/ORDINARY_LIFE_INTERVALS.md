# 事件之间的普通生活

本轮恢复被连续事件路由挤掉的普通年份。边镇线素材版本为 2.4.0，运行版本仍为 20；其他路线和旧存档快照不自动变化。

## 分工与运行

人工在合适的目标单元上配置可选的 `lifeBefore: { minYears, maxYears, context }`。规划仍只选择下一事件 ID，不选择生活年数，也不生成额外的过渡规划。无配置的衔接直接继续，连续救援、战斗、选择与结果不插入生活。

目标单元确定后，引擎根据本局种子、幕、组和单元身份，在范围内一次选定年数，保存 `eventFlow.lifeInterval` 的起止年龄。此状态在请求前保存，读档和重试复用；没有成功提交正文就不消耗年数。经过的组前属性准备同时计入这一间隔，不在达标后再重复等待。

间隔未满时走原有普通年份入口，每段沿用世界配置的 1—3 年跨度，并受剩余年数约束。普通正文只收到相应生活背景，不收到待执行单元的情境、预定结果、检定和选项。动态任务说明“本段为事件之间的普通生活，后续事件另行展开”；生活素材明确尚未入伍、仍按士兵身份等当前身份，避免提前写成下一事件已经发生。年龄、年度收益、求生、历史与展示同步沿用实际年份的原有结算。普通年份不会完成事件单元、领取其道具或调用组末观察与路由。

间隔结束后执行先前选中的单元，不重新抽取。事件正文和结果继续决定同年／跨年；生活间隔允许岁月经过，不把连续行动改成强制跨年，也不规定事件本身要写几年。不设置全局结局年龄。

## 验收

290 项后端回归通过，共享、后端和前端构建通过。规则检查覆盖一次选定、保存恢复、失败不扣年数、准备年数共用、完成不重抽，以及无配置的连续事件。两种 provider 的生活请求均不执行待开始事件、不改变玩法库存，年龄变化不改固定职责和工具。

完整新局 `run_1793987166076` 使用已授权限额 key 与隔离存储，74 岁好结局。72 条公开记录，其中 32 条普通生活，完成 33 个事件单元、10 个事件组、6 次抉择。第一幕实际事件为 7—24 岁，第二幕 32—61 岁，第三幕 70—74 岁；其间的幕初缓冲、成长与日常照常计入人生。

15 段素材生活间隔实际经过 39 年；加上早年、准备及幕初缓冲，普通年份共 49 年。山中失败进入被俘与脱逃，狼谷失利后重整，守渡与边外出击后依实际功过授偏将，全面战争决胜后军议、战后生活、卸差收束。70 岁的入侵、接防、首次交战、换防、合围与决战连续承接，没有被生活间隔拆开。

完整局仍反复出现轮值木牌、母亲递盐等意象，25—26岁重复叙述添子消息；结局总结也将正式入伍年龄说成21岁，与23岁的实际单元不一致。恢复普通年份没有解决所有复述与摘要准确性问题。本轮没有把这些问题当成接口验收通过，也没有继续添加全文改写或剧情审核请求。

第二幕世界卡的 `situation` 提前写成已经授队正，而实际路由仍要经过士兵服役和首次带队单元（`model-0074.json`）。普通生活的当前身份已在素材中明确为士兵；这并未消除世界卡自身将候选经历写成开幕事实的问题。本轮未改幕初世界卡职责，不能将74岁正常结束解释为其全部内容已经准确。

两次同步纠正分别是模型多交了 `sync_events_placeholder`、更新未登记的 `blade`；既有纠正机制成功处理。它们计入前述请求量和耗时，不因服务器没有报最终失败就记作零纠正。本轮没有改动展示维护协议。
