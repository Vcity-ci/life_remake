## 二、长期记忆按批次替换

旧路径：旧人生摘要＋新增原文 → 模型重写完整人生摘要 → 覆盖全局摘要。这使第一次留下的意象与细节持续进入每次压缩。

现在：选取未覆盖的一段实际经历 → 仅提交这个时段原文 → 返回大事概要 → 引擎追加该时段摘要，并仅替换其覆盖来源。后一批不读取、不重写前一批摘要。

- 沿用十年、幕末与终局处理机会；跨年正文按完整来源处理，不拆开同一段正文。
- 输入只有一个时期范围与本批完整实际对话，不再逐条附加年龄标题。
- 选择背景、实际选择、结果保持完整，未选择分支不混入历史。
- 来源 ID 仍由引擎精确覆盖，同年不同事件不会因年龄相同被误删。
- 后台返回时保留期间新增正文；失败保留原文，过期版本不写入。
- 各时段摘要通过同一个历史入口供应；人物简介、资产与会话摘要不再构成另一套来源。
- 身份归并按摘要 ID 保留各时期，不再按 `scope=run` 把它们折叠；恢复也不截掉第 65 份之后的摘要。

最终职责见 `narrative/task-contracts.ts`；工具字段只说明“本时段的大事概要”。覆盖哪些原文完全由引擎记录，未交给模型作为保留一切细节的写作任务。

最终压缩 system 职责：

> 将这一时期的正文压缩成简短的大事记，供后续续写。用两三句话概括重要转折与已经落定的结果，省略日常动作、对话和办理过程。不补充原文没有的事实。

这里的篇幅是生成要求，没有字数校验、输出截断或第二次整理请求。实际回放仍保留了少量训练、值守与战术细节，不能把“按时段替换已经贯通”说成“所有过程细节已经消失”。

## 三、收束与接组分别交接

旧链路同时让观察器判断幕末与选择下一组。完整组后 `ongoing` 被校验拒绝，`next_flow` 又必须填写一个合法候选。候选为空时，纠正请求能够把语义判断推向强行结束。

现在完整组后依次执行：

1. `observe_act_closure` 只取得完整幕卡、IF 标准、实际历史与已选定结果，返回 `ongoing / act_closed / run_ended`；不读候选。
2. 只有 `ongoing` 才调用独立的 `plan_next_event_flow`，接收当前年龄和属性、上一组确定结果、真实历史、本幕候选；只返回 `nextFlowId`。
3. 收束判断及接组结果分别保存，重试不重做正文、结算、掷点或已成功观察。
4. 无候选是规划素材／接组缺口，保留待处理来源并报错，不用纠正请求要求观察器改判。
5. 组内继续原组，不每段重新抽组。换幕、结局与求生仍走原提交入口。

实测还复现了旧纠正标签 `final_act_requires_run_ending` 的单向影响：它使“尚未结束大战”的错误幕收束转成普通结局。最终改为 `final_act_has_no_next_act`，明确可选 `ongoing` 或 `run_ended`，不给纠正请求指定结局答案。

固定职责、工具与本幕资料保持在前；年龄、历史、实际结果与候选放在动态请求。未恢复资产召回，也未修改前端展示、玩法数值或 IF 目标。
