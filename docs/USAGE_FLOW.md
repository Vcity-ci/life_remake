# 使用流程（v1.0.1）

## 当前体验增量：2026-09-21 +08:00

1. 玩家先选择基础世界，再选择该世界下的一条 IF 人生路线。路线卡展示名称、定位和简介；没有有效路线的世界不会开放开始按钮。
2. 人设、属性与天赋仍决定这个人怎样进入路线。身世与 Session Premise 同时接收所选路线的入口视角和长期承诺，不把不同人设写成同一个固定主角。
3. 每条路线拥有三个阶段，每阶段继续使用 `setup → escalation → pressure → climax → payoff`。模型生成具体人物、地点、本领、事件和抉择，引擎仍负责能力准入、节拍迁移、属性、生存和结局资格。
4. 路线完成后仍由模型申请结局、引擎裁决品质。死亡链路不受路线选择影响。
5. 运行态和存档保存所选路线快照；保存列表与局内人物栏显示路线名称。作者修改子世界包只影响之后的新局。

古代权谋、现代都市和奇幻世界均已完成迁移，各提供六条 IF 线。切换世界后，路线卡由 bootstrap 中对应世界的实际子包动态生成。

## 当前体验增量：2026-09-20 03:44 +08:00

1. 玩家分配属性、填写人设并确认最终天赋后，模型先生成可折叠身世；随后系统在后台建立本局故事前提。它把人设中的高概念经历视为本局承诺，而不是把所有人物压回世界包的固定开场。
2. 普通人生段继续承担年龄、生活与属性缓冲。具备准入能力时，主线场景进入五拍；模型可按需借用故事形态和社会力量，但玩家不会看到内部 ID。
3. 每个已生成场景由独立观察请求判断这一拍应保持还是推进。观察器不输出玩家正文；引擎确认后才改变节拍。需要选择的场景会先停在当前拍，玩家作答并生成后果后再判断。
4. 三个长期结构段完成后才开放非死亡结局申请。好、普通或坏结局评价完整人生，不再要求某条路线走到终点；死亡仍沿用年度体魄风险与濒死选择。

## 当前游玩流程：2026-09-10 00:26 +08:00

本节是当前用户操作入口。后文旧版的难度选择、随机抉择年龄概率与 ascended 结局描述保留为历史记录，当前流程以本节为准。

1. **确认环境**：Setting 可选择后端提供的世界。仓库包含古代权谋、奇幻修仙、现代都市；本地模式填写模型参数与密钥，云端使用服务器配置。难度按钮不展示。
2. **建立人物**：填写人设、分配五维属性、选定 1 至 3 张天赋并开始游戏。系统自动生成身世，在折叠页展示正文与选定天赋。
3. **踏入人生**：身世完成后通过主推进按钮选择本幕成长方向；方向选择位于 setup 前。后续按钮继续推进，每幕开始时再次选择成长方向。
4. **生活与场景**：普通人生段以可变年龄跨度描述生活并结算成长；属性满足相应准入后进入主线拍点。场景可以在同年连续发生，抉择提交后渲染并结算对应后果。
5. **阅读与档案**：时间线可独立向上滚动；侧栏展示属性档位、命运人物、足迹与本领。回合记录保留年龄范围、正文、选项及公开属性／资产快照。
6. **生存危机**：长期低体魄可能触发自愈、请求帮助、听天由命三项选择，分别使用智力、魅力、气运档位。成功恢复体魄，失败进入有死因的死亡结算；家境按实际年份影响体魄。
7. **主线结算**：三幕完成及既有收束条件满足后，由模型申请结局、引擎审批。属性、天赋、名望和历史代价参与好／普通／坏品质判定，年龄不强制终止主线。
8. **存档与重置**：手动存档、恢复码和抉择前检查点支持恢复与分支探索；重置匿名存档清除当前会话的局与存档。当前数据仍由服务端文件仓储保存。
9. **查看用量**：在 Setting 的模型用量区查看本会话请求与已上报 Token，必要时点击刷新；面板不显示账户余额或精确费用。

世界内容概览见 [README](../README.md#世界与-if-路线)，生存数值及更新逻辑见 [技术文档](./TECHNICAL.md)。

## 1. 启动项目

### 1.1 本地链路（开发推荐）
1. 在项目根目录执行：`npm run dev:local`（或双击 `start-local.bat`）
2. 脚本会做：
   - Node/npm 检查
   - 依赖缺失时执行 `npm install`
   - 尝试释放 `5173/4000` 端口
3. 浏览器访问：`http://localhost:5173`

### 1.2 云端链路（体验站）
1. 在服务器项目根目录执行构建并启动后端服务
2. 浏览器通过域名访问前端
3. 前端请求同域 `/api/*`，由反代转发到后端 `127.0.0.1:4000`

## 2. 进入游戏前（Setting）
1. 点击左上角 `Setting`
2. 在“会话配置”确认：
   - 部署链路（本地/云端）
   - 世界观
   - 难度
   - 本地模式下填写本地 API Key 与模型参数
3. 点击“确认本局环境”
4. 状态显示“已确认”后关闭 Setting

## 3. 创建角色并开局
1. 输入人设提示词（长度 `4~500`）
2. 分配五维属性：`智力/魅力/家境/气运/体魄`
3. 属性规则：
   - 每项 `0~10`
   - 总和必须等于本局抽到的 `talentPointTotal`
4. 选择天赋卡（数量必须在 `selectedCardMin~selectedCardMax`）
5. 点击“开始游戏”

## 4. 流式推进顺序（当前默认）
开局与推进默认使用 NDJSON 流式事件：

1. `started`：先进入局内页面（此时不下发 milestone）
2. `timeline`：逐条推送年份文本（AI 生成完成后才发）
3. `meta`：附带本段推进元数据
4. `milestone`：若触发抉择，AI 文案就绪后下发
5. `done`：本轮推进结束

说明：
- `started` 阶段不下发抉择，避免前端先挂 fallback 选项文案。
- 前端“抉择历史”会在收到该抉择年的 `timeline` 文本后再挂载记录。

## 5. 年份与抉择

### 5.1 年份类型
- 普通年
- 异动年（小事件）
- 关键抉择年（milestone）

### 5.2 抉择触发规则
- `minEligibleAge` 前不触发（默认 `5` 岁前禁触发）
- 按年龄阶段概率随机：
  - 幼年：`0.05`
  - 青年：`0.1`
  - 壮年/中年/老年：`0.15`
- 连续 `guaranteeYears` 未触发保底触发（默认 `20` 年）
- 触发背景种子从 `data/events/faction-events.json` 对应世界事件池随机抽取

### 5.3 决策后的显示
- 时间线中展示该抉择年的叙事文本与属性变化
- “抉择历史”展示：
  - 年龄与阶段
  - 抉择背景
  - 选择项（A/B/C）
  - 掷点结果胶囊（来自该 milestone 年份 `statChanges`）

### 5.4 推进状态机（2026-06-01 修复）
- 点击“继续推进年份”后进入等待态，直到服务端返回当次 `timeline/done`
- 当次流转结束后，前端会统一释放一次推进计数，避免等待态卡死
- 对于重复时间线片段，前端在缓冲区做去重，不影响本次推进计数释放
- 目标行为：抉择（A/B/C）提交后，能稳定回到“继续推进年份”循环

## 6. 结局与重开
1. 结局状态仅有：
   - `dead`（死亡）
   - `ascended`（飞升）
2. 结束后显示结算弹窗与结局文案
3. 点击“重开”后需重新确认 Setting

## 7. 常见问题
- `missing_game_environment_config`
  - 未先在 Setting 点击“确认本局环境”
- `deploy_mode_env_mismatch`
  - 启动链路与已确认会话模式不一致
- 本地模式开局失败
  - 检查本地 API Key 与模型配置
- 年份文本异常短或无输出
  - 检查模型可用性、超时、key
  - 空文本会触发后端 fallback 文案

## 8. 当前叙事体验说明（2026-08-15 01:22 +08:00，增量）

> 本节补充叙事世界包启用后的实际体验；如与第 5、6 节的旧随机触发与结局描述冲突，以本节为准。

1. 普通推进会展示一段或数年连续的成长背景，年龄跨度由当前世界包节拍决定。它用于积累属性、人物关系和已发生事件的余波，不显示路线、标签或系统阶段。
2. 抉择只在已建立的冲突需要行动时出现。选择后的代价会影响后续场景与结局质量，不能由模型凭空回收未发生的伏笔。
3. 游戏不会因达到固定年龄自动结束。完成当前主线的伏笔、压力、高潮和回收后，才进入收束；此时引擎根据角色属性、天赋卡、道具和历史代价确定好/坏结局方向。
4. 若结局收束时模型暂时无法按协议响应，游戏不会跳到无关年份，也不会把内部错误展示为玩家文本；继续推进会停留在该结局引导链。

## 9. 当前叙事节奏补充（2026-08-21 01:29 +08:00，增量）

1. 玩家看见的仍是一条连续人生时间线，不会看到“路线”“节拍”“世界幕”或工具调用标签。
2. 模型可以在同一世界主线下切换人物经历视角，例如先处理家门、再转入仕途或商路；未完成经历会保留其叙事进度，后续可以自然回到该经历。
3. 任一经历完成本幕高潮与回收后，故事进入下一层世界矛盾。当前古代线依次由旧案显形进入阵营周旋，再进入北境救国；不是走完某一条单线就结束人生。
4. 抉择仍只在压力和高潮的关键处出现。普通年份可以平缓推进成长、关系与余波；重大连续事件可保持同龄叙事，由既有场景节拍控制。
5. 三次世界幕回收完成后，模型才可申请结局；引擎再依据既有属性、天赋、道具和历史代价决定结局走向。

## 10. 生存、天赋与命运人物（2026-08-25 14:54 +08:00，增量）

1. 体魄不会因单次低值直接导致死亡。实际跨年后，若体魄连续低于当前年龄阶段的风险线，才会累计风险；通过世界包宽限期与概率审核后，游戏暂停在“生存危机”。
2. 生存危机显示三项玩家选择：自愈看智力、请求帮助看魅力、听天由命看气运。属性为高档时该选择必定成功；成功后体魄恢复，失败后本局进入死亡结算，并以既有故事为上下文渲染死因。
3. 开局仍只能选择配置允许数量的天赋卡，当前默认是 1 至 3 张。已选天赋会显示在折叠的身世卡与侧栏，也会作为人物倾向进入后续叙事；未选择的卡不会影响本局。
4. “命运人物”只显示被标记为可回归的角色。相同角色再次出现时会更新既有身份而不是新增同名标签；一次性路人不会进入该列表。
