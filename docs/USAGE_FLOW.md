# 使用流程

更新于 2026-11-06。当前为原型版本；边镇将帅采用事件组运行版本 20，其他 IF 采用运行版本 18。以下描述当前入口，旧随机里程碑、五节拍与到龄飞升不作为操作依据。

## 启动与配置

1. 安装 Node.js 24.x，在项目根目录运行 `start-local.bat`。
2. 浏览器访问 `http://localhost:5173`，打开 Setting。
3. 本地模式填写模型服务的 API Key、Base URL、模型和支持的接口，确认本局环境。云端模式使用服务器配置。
4. 选择世界与 IF，填写人设、分配系统给出的属性点、选择允许数量的天赋，开始新局。

端口和模板见根目录 README。真实密钥保存在本地环境或当前进程会话，不写进源码与持久化游戏存档。浏览器访问模型故事时，后端仍需向配置的模型服务发请求。

## 身世、准备与推进

- 身世停在出生时，展示家庭环境与预设身份。身世原文是实际历史，没有另一份身世摘要。
- 选择成长方向后继续。世界卡准备期间可经过有限过渡生活；就绪后依据本幕局势准备。
- 关键属性分别达标后进入剧情，取得的准入不会因后续下降丢失。边镇部分事件组有自己的组前准备，入组后连续执行。
- 时间线显示已提交正文，顶部幕序跟随最新已展示正文。后台进入下一幕不会提前改变旧幕末段的标记。
- 正文可交接同年或下一年；同年也可以涵盖本岁内合理的训练、旅行和行动，不等于每轮只推进一分钟。

普通年份允许生活与成长。当前训练、值守与摘要细节仍可能重复，属于实测未解决项，不能因同年功能正常就认定故事推进已合格。

## 抉择与完整事件

边镇线的人工事件组预先定义完整事件、三种行动、检定属性及难度。玩家看到正文后选择一项，引擎保存一次掷点；独立结果正文落实已经确定的成功或失败。

- 提出选择不提前提交玩家行动及其结果。
- 背景、玩家作答、结果和求生保持同一事件年龄。
- 保存后的结果重试复用，不重新生成或掷点。
- 失败可以进入重整、失援或其他后续经历；局部失败不自动等于整局结束。
- 完整组结束后才选择新组；组内不另抽一组覆盖未完成经历。

其他 IF 保留自由主持整幕的正文入口；不将边镇事件组配置描述为所有路线都已具备。

## 档案与道具

人物、足迹、本领和道具在侧栏展示。边镇只维护预设角色卡的简短当前状态，经历留在时间线。展示资料不回流正文，不承担剧情前置任务。

道具的实际获得、交付和消耗由事件结果更新；展示同步不能发放道具。同步失败保留待整理经历，不要求玩家重新经历已提交事件。

## 收束与结局

观察器根据实际故事和 IF 标准判断继续、换幕或整局结束。边镇线尚未收束时，独立规划依据上一组结果选择下一组；一次任务完成不自动结束整幕。

已经成立的提前结局可以结束本局，不要求把三幕补齐。整局结束时确认结局等级；涉及生死时同时确认实际生死与必要死因，再生成结局正文。属性与求生仍按既有规则执行。

## 存档与恢复

- 匿名会话通过 HttpOnly Cookie 隔离。手动存档、抉择检查点和恢复码沿现有入口使用。
- 读档创建当前分支，原存档保留。新旧协议不自动语义迁移；不兼容旧局只读查看。
- 失败后再次推进先恢复已保存事件的待处理收尾，不先生成新的年份。
- 运行数据位于 `storage/`，不随 Git 保存。备份或换设备应单独处理运行文件与恢复码。

历史压缩只替换模型后续读取的上下文，玩家原始时间线保留可见记录。各时段概要只覆盖明确来源，同年追加经历仍作为原文承接。

## 常见定位入口

| 表现 | 先检查 |
| --- | --- |
| 环境未确认、模式不匹配 | Setting 与后端部署模式 |
| 模型超时或返回格式错误 | 本次最终请求、工具原始返回与具体校验错误 |
| 故事已提交但下一组未进入 | 待收尾记录、观察结果与独立接组规划；不要重开同一事件 |
| 人物卡没有及时整理 | 连续性批次与错误日志；不能反过来把展示结果当作故事事实 |
| 重复叙事、细节循环 | 该段最终输入、世界卡、真实历史与压缩输出；不要仅凭某个词或属性推断 |

更多入口见[文档索引](README.md)、[完整架构](ARCHITECTURE.md)与[文件管理](REPOSITORY_HYGIENE.md)。
