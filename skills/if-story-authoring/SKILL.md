# IF 故事创作

让一条人生主线具有可承接的经历、真实选择、非成功后续和成立的结局。作者决定故事材料，规划只在合法接续中选 ID，正文表达当前经历，观察器判断实际收束。

## 创作前先对齐

阅读目标 IF、事件组、所属世界制度和对应作者表。当前协议见 [事件协议](../../docs/EVENT_FLOW_IMPLEMENTATION.md)；样本分别见 [边境作者表](../../docs/FRONTIER_BRANCH_PILOT.md) 和 [逐鹿作者表](../../docs/SOVEREIGN_BRANCH_PILOT.md)。旧验收记录只说明对应版本的事实。

开始新增或调整故事时，先读[修改位置与固定产出](references/content-deliverables.md)，定位世界观、IF、事件组和开发记录各自要改的字段。不要把同一套剧情复制到各层，也不要因故事不同就默认修改引擎。

先提出作者分支表，向用户交代预计故事和必要代码协调，按已获得的确认继续。表中逐项写明：一件事、实际结果、允许接续，以及生活承接什么变化。区分：

- 主线成果：本幕实际要回答的问题。
- 等价经历：不同事件均能承担相近的成长作用，无须全部完成。
- 辅助经历：可选收获，不替代主线成果。
- 决定性选择：确实改变立场或人生去向，需要玩家作答。
- 后果处理：承接损失、奖惩与交接，不是原任务的补考。

作者表仅供开发，不增加运行时加载器，不作为模型的第二份剧情指导。不要从现有语料自行膨胀故事范围，也不要把军旅样本的内容当作其他题材的模板。

## 落实到事件组

协议字段、合法节点及校验以当前类型、加载器为准。新推广素材声明 `protocolVersion: 2`、各幕 `actEntries` 和每个结果的明确接续；执行能力由协议决定，不能通过世界、IF ID 或职衔名称分支。

每个单元处理一件有内容的事。行动检定裁定执行成败；直接选择决定目标或去向，不伪造 roll；奖惩单元依世界规则处理已经发生的功过。普通疑问和既定目标下的行动安排可以由正文推演，不必一律停下提问。

逐个核对非成功结果：损失带到哪里，剩余力量能做什么，何种实际败亡可以结束。结果可以汇合，但不能补发未取得的兵力、财产、地位或认可。共同收尾只处理真实所得。已完成事件不因“仍有其他事情”重新开放。

组内未结束不抽新组。`nextEventIds` 与结束组的 `nextFlowIds` 承载允许范围；多候选由规划选择，单候选直接承接。无合法后续应暴露素材断点，不能退回整幕自由抽取或迫使观察器宣布完成。

在适合的位置配置普通生活间隔，以身份、家庭、同伴与职责的实际变化提供内容。沿用年数范围、种子选定和保存恢复；事件时长与正文时间交接保持各自职责。不要用最低年龄、重复训练或新增逐年任务凑人生长度。

## 核对模型实际收到什么

幕初只组织稳定主持资料和角色具象化；幕内路由只选当前合法引用。正文只收到当前单元，结果只收到已选结果，未选未来分支不进入正文。世界卡不提前写入尚未取得的认知、立场和战果。

检查最终发送请求，而非仅查提示词定义：固定职责、工具和稳定世界卡在前；实际历史、人物状态、当前单元及本段年龄在后。历史只有一个入口，目录、成败和年龄不改写 system 或 schema。

本项目当前资产维护只供展示，不恢复正文资产召回。遇到重复，先定位身世、世界卡、历史、当前单元、生活材料及最终组装中的实际来源；不要叠加“不要重复”指令、关键词过滤或正文重写请求。

## 验证和针对性修改

先验证选择提交、接续、失败、汇合、同年、恢复、求生及终局交接，再使用 `scripts/live-narrative-check.mjs` 隔离实测。读取脚本当前参数，按具体节点和选项 ID 选择路径；没有明确策略时不能偷偷选第一个选项。

需要真实模型调用时遵循本轮用户的授权和额度；本项目已约定的测试凭据位于 `Material/ak.txt`。凭据只用于请求，不输出或写入抓包，测试不覆盖玩家存档。已有选择、掷点和结果在重试中复用，不改点数制造指定路线。

保留最终请求、原始返回、实际写入和可读故事。发现接续错误改对应引用；成果跳跃改对应单元；重复供应改实际组装；提交错误改执行链。先复测受影响片段，再核对完整故事。片段续跑不能称为另一轮完整新局。

分别报告：执行正确性、分支完整性、生活重复和叙事效果。能够结局、年龄增长、测试通过都不能代替故事验收。模型误判等级、遗漏生死或素材仍重复时明确记录；不得把未覆盖的随机分支写成已验证。
