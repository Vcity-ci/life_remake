# 修改位置与固定产出

这份定位用于开发者与开发模型，不加入游戏模型输入。先用作者表说明故事，再决定哪些来源确实需要改变。

| 层次／位置 | 应修改的内容 | 固定产出与核对 |
| --- | --- | --- |
| 世界观：`data/narratives/world-cards/<world>/`、所属世界定义 | 规律、制度、空间与行动条件；卡的 `content` 表达可实际使用的世界知识 | 哪些现实条件让行动成立、受限或产生后果；检查引用者，避免为单条 IF 改写其他题材 |
| IF：`data/narratives/story-packs/<world>/<route>.json` | 路线承诺与人物方向；各幕 `objective / payoffMeaning`；`adventureSeeds`；`endingDirections`；必要卡引用 | 一条明确人生主线、各幕成果和结局边界；介绍只概述，具体事件不在每个字段重复 |
| 事件组：`data/narratives/event-flows/<route-id>.json` | `actEntries`、组入口、单元、确定结果、接续、生活间隔、角色与道具 | 完整经历及非成功后续；每个单元一件事，结果只交付实际所得，辅助经历接回其服务的主线 |
| 作者表：对应 `docs/*BRANCH*.md` 或已有路线创作文件 | 主线、等价经历、辅助经历、决定性选择、失败后果；素材保留／合并／删除及映射 | 用户可审读的完整故事链与覆盖表；不是运行素材，不增加加载器或第二份剧情真相 |
| 验证记录：作者表当前验收段及隔离 `storage/verification-*` | 选择策略、最终请求、原始返回、实际写入、可读故事、回放来源 | 执行与故事分别结论；标明新局或片段、实际路径、耗时、失败及未覆盖项 |

## 字段如何分工

世界卡解释占地、合作或权力转移怎样成立，不安排一次具体攻城；IF 说明本幕要回答的整体问题，不列当轮任务；事件组才落实这座城、这场行动和后续。只因介绍换了表述，不需要同步重写其余各层。

事件角色的 `identity` 是身份与性质；实际状态来自展示维护。不要用角色身份、固定物件或每段生活要求重复安排查账、认人或证明资格。方法材料需要时保留，但不能把物件等同于取得土地或获得政治认可。

`lifeBefore` 负责事件之间的生活空间。上下文应匹配当前阶段和真实关系，不预写后续战果；普通生活的长度与事件正文的同年／跨年交接各有来源。

## 何时改代码

- 当前节点类型、接续、道具与时间协议能够表达故事时，修改素材及相应测试策略。
- 只有明确缺少一种跨题材可复用的能力，才提出通用协议修改，并交代类型、工具、解析、提交与恢复的完整路径。
- 引用错误、假成果和失败无后续属于素材或接续问题，不通过 IF ID、世界名、军职名特判补救。

完成后更新素材修订号和当前作者表，保持旧局快照。新规则是否需要运行版本变化由协议变化决定，不能仅因为新写了一段剧情就升运行版本。
